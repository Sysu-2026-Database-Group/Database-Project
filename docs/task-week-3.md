## 1. 任务原文

> 第三周任务 ch3 DDL与数据修改
> ==================
>
> 1\. 本周目标
> --------
>
> 使用SQL脚本从空数据库开始创建商品、库存、订单和订单明细等业务对象，完成基础数据的新增、修改、删除和查询
>
> 2\. 任务
> ------
>
> 1.  创建数据库与数据表：创建数据库，根据第二周的数据字典，为商品、库存、订单等先前设计的核心对象选择合适的数据类型并创建表。
> 2.  定义表结构：按照第二周为每张表确定字段名、数据类型、长度或精度、是否允许为空、默认值及字段含义。设置数据约束，定义主键、候选码、外键、非空约束、默认值和检查约束，保证商品、库存和订单之间的数据关系正确。
> 3.  添加样例数据：把第二周编写的样例元组转换为 INSERT 语句，使各表都有能够支持后续查询和测试的数据。
> 4.  完成增删改查：至少对商品、库存和订单相关数据分别完成插入、查询、修改和删除操作。
> 5.  验证脚本可复现：在空数据库中按说明重新执行脚本，确认能够得到相同的表结构和样例数据。
>
> 3\. 本周作业
> --------
>
> *   建库与建表脚本：包括数据库创建、核心数据表创建以及必要的数据类型说明。
> *   插入样例数据脚本：为核心表插入能够体现业务联系的样例数据。
> *   CRUD 脚本与结果：展示典型的新增、查询、修改、删除操作及执行前后的结果。
> *   复现说明：写明脚本执行顺序和从空数据库开始运行的方法。
>
> 4\. 提示与常见问题
> -----------
>
> *   先创建被外码引用的表，再创建引用它的表；删除时通常按相反顺序处理。
> *   字符串、日期和数值要使用合适的数据类型，不要把所有字段都定义成字符型。
> *   插入的样例数据尽量多一些，以便之后的实验。
> *   DELETE 和 UPDATE 必须先确认 WHERE 条件，建议先用相同条件执行 SELECT 检查目标行。
> *   样例数据要能够体现表之间的联系，不要让订单明细引用不存在的订单或商品。
> *   AI 可以协助生成候选 SQL，但必须逐句检查表名、字段名、数据类型和执行结果，并记录人工修改。
