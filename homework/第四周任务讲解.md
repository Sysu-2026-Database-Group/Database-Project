# 第四周任务讲解

> 来源：`第四周任务讲解.docx`。本文按原件整理为便于检索的 Markdown；课程原件以 DOCX 为准。

## 课程与阶段目标

**AI+数据库实验课程**第一阶段（第 1—4 周）的主题是数据库初建与 CRUD。

阶段目标：把真实经营场景转化为可运行的关系数据库，完成建库、装载、增删改查、连接查询、视图、完整性与授权。

| 周次 | 理论内容 | 项目任务 | 当周产出 | 展示重点 |
|---|---|---|---|---|
| 1 | ch1 数据库与 Data+AI | 确定经营场景、边界、角色和业务流程 | 业务流程、不同经营角色职能 | 解释哪些信息进入数据库，哪些暂不进入 |
| 2 | ch2 关系、属性、码、模式 | 把业务对象转成关系模式，定义属性、域和码 | 表清单、字段定义、码标注、真实样例元组 | 解释每个字段及其键 |
| 3 | ch3 DDL 与数据修改 | 新建数据库并完成商品、库存、订单等对象的 CRUD | 建库和 CRUD 语句，要求可复现 | 从空库构建，现场执行一组 CRUD |
| 4 | ch4 连接、视图、完整性、授权 | 完成多表查询、统计视图、约束和角色权限 | `query.sql`、`view.sql`、`constraint.sql`、`role.sql` | 非法数据被拒绝，越权操作失败，查询结果正确 |

## 第一阶段作业：可运行的数据库原型（v0.1）

- README：项目范围、业务角色、业务流程、脚本执行顺序与复现步骤。
- SQL 目录：建库、样例数据、CRUD、查询与视图、约束与角色的 SQL，包含之前每周任务的要求。
- 结果目录：成功建库、正常用例、非法数据、越权访问、关键查询、CRUD、统计视图及不同角色权限的结果截图，包含之前每周任务的要求。
- 阶段报告：设计思路、实验过程、实验总结；重点说明经营场景与业务流程、数据边界及理由、表与码的设计及理由、完整性约束和角色权限的正反例。
- `ai_log`：记录 AI 建议、人工修改和验证结论。

AI 可以帮助判断数据边界、角色和业务流程；学生须自行判断、修改并解释，自行完成建库，用反例、约束和执行结果证明正确性。

## 第四周任务：ch4 连接、视图、完整性、授权

### 1. 本周目标

完成多表查询、统计视图、主外键与检查约束、角色权限。

### 2. 任务

1. **多表查询**：围绕订单、订单明细、商品、会员等表编写连接查询，回答完整的业务问题。
2. **统计查询**：使用聚合函数、`GROUP BY`、`HAVING` 和必要的子查询，统计销量、销售额、库存或会员消费情况。
3. **统计视图**：把会重复使用的统计查询封装为视图，并验证结果，如订单详情、商品销售统计和库存状态视图。
4. **完整性约束**：检查并完善主码、外码、`UNIQUE`、`CHECK`、`DEFAULT`、空值约束。
5. **角色权限**：依据第一周角色清单创建数据库角色，授予所需的最小权限，并测试越权操作。
6. **v0.1 复现**：从空数据库依次运行建库、样例数据、查询、视图、约束和权限脚本。

### 3. 本周作业

- `query.sql`：多表连接、聚合和子查询，具有明确业务含义。
- `view.sql`：创建并查询不同的统计视图。
- `constraint.sql`：创建约束，并含合法数据成功、非法数据失败的验证用例。
- `role.sql`：创建角色、授予权限，并展示正常操作与越权失败。
- v0.1 阶段验收清单：README、SQL 目录、结果目录、阶段报告、`ai_log` 和组内分工齐全；按 README 从空库可复现。

### 4. 提示与常见问题

- `INNER JOIN` 和 `LEFT JOIN` 的结果不同，应按业务问题选择并解释。
- 完整性约束要在数据库中生效，不能只写在报告中。
- 角色权限遵循最小权限原则，不应直接授予数据库所有权限。
- 截图只是证据，提交内容仍要包含可重新执行的 SQL。
- AI 生成的查询可能语法正确而业务含义错误，须用样例数据和预期结果核对。
