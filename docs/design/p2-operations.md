# P2 商品、资金与采购入口

实施日期：2026-11-02。正式范围仍以 [Web规划](plan-web-development.md) 和 [唯一台账](../tasks/task-web-development.md) 为准。

调用链为 `routes/operations.py` → `OperationsService` → `EmployeeDAO` → `api.usp_operation_*`。HTTP层从已验证会话取主体，不接受前端操作人；服务层拒绝未知字段，金额限正数及两位小数。SQL以固定动作白名单复核数据库角色、员工岗位、会话版本及业务状态，无动态SQL；精确授权过程，不授予底表访问。

`api.operation_request` 存储员工、UUID请求键、动作、规范化内容SHA-256和原结果，作为销售请求表之外共享的P2请求记录，不新增经营实体。请求记录、单据和流水在一个事务提交，同键不同内容拒绝。同键成功重试先返回原结果，再考虑预览过期或状态变化。表单303跳转，连接失败或死锁时保留原输入和请求键供重试。

注资、采购付款先只读预览再签名确认。凭据绑定员工/会话、动作、输入、请求键、金额及数据库给出的10分钟有效期。确认事务复核金额、审批、未付及余额条件。注资增加现金但不计经营收入；提现和完整经营报表仍属P5。

库管建立商品时售价为空、未上架、库存及已订量均为0；资料编辑不改类别和业务编码。店长独立定价上下架，不改旧成交快照。采购批次价冻结在明细中，不随供应商当前报价变化。采购沿用草稿→已提交→已审批→已收货，草稿/已提交可取消。库管维护单供应商草稿及明细，提交后冻结；店长审批、一次付款；库管付款后整单收货，增加库存并写购入流水。报损必须原因，只消耗可售量。

## 锁定顺序

| 动作 | 请求/单据与中间资源 | 商品 | 资金 |
|---|---|---|---|
| 原销售 | 销售请求→会员/卡参数 | 按ID升序 | 最后资金行/范围UPDLOCK,HOLDLOCK |
| 注资 | 操作请求 | 无 | 同销售资金锁 |
| 草稿/提交/取消/审批 | 操作请求→采购单→明细/FK | 不改库存 | 无 |
| 采购付款 | 操作请求→采购单→冻结明细 | 不改库存 | 同销售资金锁 |
| 收货 | 操作请求→采购单→付款事实只读检查 | 按ID升序锁定并写流水 | 不再写资金 |
| 报损 | 操作请求 | 单商品条件更新→流水 | 无 |
| 资料/供应商/报价 | 操作请求→事务级catalog应用锁→业务键/FK | 不直接改库存 | 无 |
| 定价 | 操作请求 | 单商品更新 | 无 |

XACT_ABORT保证失败回滚业务及请求记录。新增过程不先持有资金写锁再等待商品写锁；死锁按统一409处理并用原请求重试。未来预订、退款、会员流程须继续扩展资源顺序表。真实检查应验证回滚及余额链，不承诺完全没有死锁。

runner自动在两个新隔离副本安装新过程并核查授权。P2多数SQL测试用真实受限数据库用户并在事务内回滚；注资/销售并发使用独立SQL登录。结束核对19张经营表指纹、两类请求表及凭据/用户清理。既有运行库未升级，不重新setup覆盖配置和口令。

剩余：人工浏览器/响应式、跨机/ODBC18、采购多连接并发收货/付款与取消竞争、顾客公开商品（P3）、提现/报表（P5）。自动化通过不等同整个项目完成。
