## 1 `employee` 员工

**一行 = 一名员工** ｜ 图中角色：**实体**（主体）

### 1.1 定位与标识

- **定位**：店内**唯一的人员档案**（店长 / 收银员 / 库管）；全库**所有留痕列**（`_by` / `set_by`）都指向它；岗位（`role`）决定"谁能做什么"。
- **是否独立保存**：**是** —— ① 被近 20 条外码引用 ② 有自己的生命周期（建账号 → 改岗位）③ 岗位本身是业务规则的一部分。
- **主标识**：**`phone`（手机号）**　**候选标识**：无（`phone` 即主标识）
  - 取舍理由：**账号就是手机号**（A18），"认人也认它" —— 属"**业务键做主键**"那一类。
- **依据**：A18 · R-22 §4（发账号要有出处）。

### 1.2 属性

| 属性类别 | 字段 | 说明 |
|---|---|---|
| **键属性** | `phone` | 主标识 |
| 普通属性 | `name` · `role` | `role` 为枚举（库管 / 收银员 / 店长） |
| **自引用外码** | `created_by`（**非空**）· `updated_by`（**可空**） | 均 → `employee.phone`；前者是"账号维护人 = 店长" |
| 时刻属性 | `created_at` · `updated_at`（可空） | `updated_at` 与 `updated_by` **同空同非空** |
| **明确不做** | —— | **登录口令不进本表**（账号机制实现细节，字典已写"另定"） |

> **用词说明**：`role` 用「**库管**」= `spec-roles.md` 的「**库存管理员**」—— 同一岗位（`README.md` §3.1 已声明等价）。

## 2 `card_type` 会员卡档位

**一行 = 一个档位的当前参数** ｜ 图中角色：**实体**（参数）

### 2.1 定位与标识

- **定位**：会员卡的**当前配置**（银卡 / 金卡各一行）；店长可改，**改后只影响之后的业务**。
- **是否独立保存**：**是** —— ① 被 `member.card_level` 引用 ② 是**参数的唯一出处**（成交时快照进 `sale`）③ 有自己的维护动作与留痕。
- **主标识**：**`level`（档位名）**　**候选标识**：无
  - 取舍理由：档位是**受控的小枚举**（只有两个值），加代理键反而多一次连接（字典 §0.4）。
- **依据**：A16 · R-17。

### 2.2 属性

| 属性类别 | 字段 | 说明 |
|---|---|---|
| **键属性** | `level` | 枚举（银卡 / 金卡） |
| 参数属性 | `card_fee` · `discount_rate` | 域含**跨行比较**：金卡费 > 银卡费 · 金卡折扣率 ≤ 银卡折扣率 |
| 留痕属性 | `set_by`（非空，**仅店长**）· `set_at` | ⚠️ **命名例外**：本表用 `set_by` / `set_at`，不是通用的 `_by` / `_at` |
| **明确不做** | —— | **不留参数变更历史**（只有当前值 + 最近设定时刻）→ **I-03** |

> **明文规定**：店长改参数**只更新当前行**，**不删除已被会员引用的档位**。

## 3 `goods` 商品与库存计数

**一行 = 一种商品（含未上架）及其库存计数** ｜ 图中角色：**实体**（**超类**，与 `book` / `toy` 构成"可选互斥子类"）

### 3.1 定位与标识

- **定位**：全库**被引用最密集**的表（三类单据明细、库存变动、供应商报价都指向它）；**库存计数（在架 / 已订）是它的属性**，不是独立实体。
- **是否独立保存**：**是** —— ① 被 `sale_item` / `reservation_item` / `purchase_request_item` / `stock_movement` / `supplier_quote` 引用；② 有自己的生命周期（建档 → 定价上架 → 调价 / 下架）；③ 是"能不能卖"的判断载体。
- **主标识**：**`id`（代理键，自增）**　**候选标识**：**无业务候选标识**
  - 取舍理由（字典 §0.4）："名称会重；`book_isbn` / `toy_code` 必有一个为空，**含空值的属性组不能唯一标识**" → 只能用自增代理键。
  - ⚠️ 说明：`id` **本身**仍是候选标识（唯一、极小），只是人为加的 —— "无**业务**候选标识" ≠ "没有候选标识"。
- **依据**：A1 · A2 · A4 · A5 · R-1（上架与定价）· R-21（在架）· R-23（已订）· 字典 §0.4。

### 3.2 属性

| 属性类别 | 字段 | 说明 |
|---|---|---|
| **键属性** | `id` | 代理键（自增），**统一标识两类商品** |
| 普通属性 | `category`（枚举 **图书 / 文创**）· `name`（1–100） | —— |
| **外码（可选、互斥）** | `book_isbn`（文创时为空）· `toy_code`（图书时为空） | **恰一个非空，且与 `category` 一致**（CHECK） |
| 状态属性 | `on_shelf`（`BIT`，默认 0） | 联动约束：`on_shelf = 1 ⇒ price` 非空（CHECK） |
| 金额属性 | `price`（**可空 = 未定价**；`> 0`） | 当前售价（A4、R-1） |
| **计数属性** | `stock_total`（≥ 0）· `reserved_qty`（`0 ≤ 值 ≤ stock_total`） | 域还含**跨行等式**（= 变动累加 / 有效预订行之和）→ **I-04** |
| 留痕属性 | `created_by` / `created_at`（非空）· `updated_by` / `updated_at`（可空、成对） | 属 §1.3 的 **C-2**（各类留痕汇总），此处不重复 |
| **派生（不落库）** | **可售量** = `stock_total − reserved_qty`；**能不能卖** = `on_shelf = 1 且 可售量 > 0` | 图里画**虚线椭圆**（R-2） |
| **明确不做** | —— | ① **不设商品状态机**（"待定价 / 下架 / 缺货"全部塌缩为"未上架"或现算条件，R-1）；② **不做封面图**（边界清单**不进库 #19**："不参与任何判定"） |

### 3.5 问题

### 19.5 问题

- **I-19**（拟第 6 周调整）**`fund_after` 没有非负约束** —— 只约束了 `fund_before ≥ 0`，而 `fund_after = fund_before ± amount`，于是"**付**"这一支**可以把余额压成负数**（付出超过手上的现金）；`51223` 只查**相邻衔接**、`51224` 只查**基线终值**，**都不查符号** → 库里不拦、校验也不报。
- **I-20**（拟第 6 周调整）**"办卡费"的金额没有任何校验** —— `51216`–`51219` 分别管"退款流水 ↔ 退货单""销售收款 = `paid_amount`（**恰好 1 笔**）""退货退款笔数与额""采购付款 = 明细合计"，而**办卡费**只被 `CK_fund_flow_source` 约束"必须有 `member_phone`"；R-24 的收费规则（新办按**当时档位费用**、升级按**差价**）**无落点**（办理时的参数不存快照；样例 `20.00 / 50.00 / 30.00` 恰是"银卡 / 金卡 / **升级差价 50 − 20**"）。
- **参与既有问题**：**I-14**（`51217` 就是它）· **I-17**（`51216` / `51218`）· **I-02**（岗位 —— `51221` 覆盖）· **I-16**（`51217` 的 `COUNT = 1` 是"上界"被校验补住的正例）。
- **刻意不开 issue**：① **金额不靠正负**（`amount > 0` + `direction`）—— 字典 §4.1 明文；② **注资 / 提现金额无法校验**（B14：店长自行决定投钱 / 取钱）；③ **盈亏与现金余额同表派生**（R-15 拆两个指标，`51224` 各验一个）；④ **不区分"发生 / 登记"时刻**（本阶段合一）；⑤ **办卡费只挂会员、不挂单据**（B8 的成果是"会员档案 + 档位"，见 §8）。
