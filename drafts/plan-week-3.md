## 2. 已完成的 SQL 工作

### 2.1 建库建表：`db/schema.sql`

按照当前数据字典创建 19 张表，顺序遵循被引用表先建、引用表后建。脚本包含：

- 19 个主键、9 个业务唯一约束和 47 个外键；
- `BIGINT`、`INT`、`DECIMAL`、`VARCHAR`、`NVARCHAR`、`DATE`、`DATETIME2` 等字段类型；
- `IDENTITY(1,1)` 自增列、默认值、非空约束和基础 `CHECK` 约束；
- 商品类别与图书 / 文创明细的对应关系、库存来源字段、销售金额、会员卡参数和资金方向等单行约束；
- 通过 `MS_Description` 扩展属性写入字段含义，便于在数据库中查看数据字典语义。

跨表汇总、累计退货、资金链和角色权限不假装由普通 `CHECK` 完成，留给校验查询和后续 Week 4 事务 / 权限脚本。

### 2.2 样例数据：`db/sample-data.sql`

脚本按外键依赖装载数据字典中的 77 行样例，使用 `IDENTITY_INSERT` 保留样例中的主键编号。样例覆盖：

- 商品、图书、文创、供应商和当前报价；
- 采购申请及明细、销售单及明细、预订单及明细、退货单及明细；
- 银卡和金卡当前参数、会员、积分流水、资金流水和员工；
- 库存购入、卖出、退货、损坏四类变动。

样例脚本具有保护逻辑：空表插入基线；已有内容与基线完全一致时不重复插入；内容不一致时返回错误并回滚，不覆盖已有数据。冲突样例保护已单独验证，错误码为 `51001`。

### 2.3 结构、对账与反例：`db/verify.sql`

脚本检查表数、字段类型、可空性、默认值、自增属性、主键、唯一约束、外键和字段说明，并核对跨表数据：

- 19 张表、47 个外键、77 行样例；
- 商品库存与库存流水一致；
- 有效预订与 `reserved_qty` 一致；
- 会员积分余额与积分流水一致；
- 销售单与销售明细金额一致；
- 退货金额、原销售单、退货数量、库存回收和积分回滚一致；
- 采购审批、付款、入库的时间顺序和申请数量一致；
- 资金流水首尾相接，现金余额为 `1430.30`，经营盈亏为 `−69.70`。

脚本还运行默认值正例和 16 个非法数据反例，实际得到预期的主键 / 唯一约束、外键 / 检查约束和非空错误，并在每个用例后回滚。

### 2.4 CRUD 演示：`db/crud.sql`

CRUD 脚本在一个事务中创建演示商品，完成采购草稿、审批、付款、入库、销售、退货及对应查询，再按外键依赖顺序执行删除。每次 `UPDATE` / `DELETE` 前先用相同条件 `SELECT` 确认目标；最终回滚，原样例基线保持不变。

演示覆盖：

| 对象 | INSERT | SELECT | UPDATE | DELETE |
|---|---|---|---|---|
| 商品 | 演示文创与商品 | 插入前后查询 | 设置售价与上架 | 删除事务内商品 |
| 库存相关记录 | 采购与库存变动 | 查看变动和库存 | 更新库存计数与采购状态 | 删除事务内流水 |
| 销售 / 退货单 | 销售、销售明细、退货单、退货明细 | 查询单据状态 | 状态变为已全退 | 删除事务内单据 |

## 3. 执行顺序与复现

使用 SQL Server 和 SQLCMD 模式，从新的专用空库开始按以下顺序执行：

```text
schema.sql
sample-data.sql
verify.sql
crud.sql
verify.sql
```

`schema.sql` 负责创建结构，`sample-data.sql` 负责装载基线，第一次 `verify.sql` 检查基线，`crud.sql` 演示并回滚，第二次 `verify.sql` 确认回滚没有改变基线。命令、SQLCMD 变量、SSMS SQLCMD 模式、退出码和常见失败处理见 `db/README.md`。

当前执行者已在 `ShiguangBookstoreWeek3` 和 `ShiguangBookstoreWeek3Replay` 两个新库完成上述流程，并保存原始输出。Replay 库还验证了已有表时 `schema.sql` 返回 `51000` 并停止，不覆盖已有数据。

## 4. 执行中发现的问题与修正

1. 初次样例装载的 ISO 日期时间只有小时和分钟，SQL Server 转换失败；改为完整的 `YYYY-MM-DDTHH:MM:SS` 后重新执行成功，失败事务没有留下部分数据。
2. 结构校验最初把 `DECIMAL(3,2)` 的内部存储长度按 9 字节预期，实际 SQL Server 为 5 字节；修正校验预期后通过，表字段定义没有改变。
3. CRUD、校验和样例装载脚本均增加空外层事务保护，避免在已有事务中误执行；脚本不包含删除数据库或覆盖已有经营数据的操作。
