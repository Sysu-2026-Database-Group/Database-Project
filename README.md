## 三、课程项目概览

### 3.1 项目背景

「拾光书店」是一家**单门店**书店，营业面积约 120 ㎡。
除线下零售外，它还开放**线上预订、到店自提** —— 这正是本项目最核心的设计难点：
线上与线下共享同一批库存，必须有一套能说清「谁先占了货」的模型。

| 项 | 内容 |
|---|---|
| 门店形态 | 单门店 + 线上预订自提，无物流 |
| 商品范围 | 新书（文学 / 社科 / 计算机 / 教辅）+ 文创周边；无二手书、无规格变体 |
| 员工 | 4 人、3 类岗位：店长 1 · 收银员 2 · 库管 1（**不设系统管理员**） |
| 会员体系 | 购买会员卡入会（卡一年有效）；**分银卡 / 金卡两档**；不做储值 |
| 资金口径 | 收付实现制；**店内资金总额**与**经营盈亏**分列两个指标 |

### 3.2 项目目标

本项目是一次**数据库设计练习**，不是 Web 工程练习。做得好不好，只看两条：

1. **数据建模是否规范** —— ER 是否正确、关系模式是否达到 3NF、约束是否完整。
2. **数据流动是否可解释** —— 每个业务动作引起的表级变化，能否说清、查到、回滚。

由此推出一条贯穿全项目的原则：**应用层刻意做薄**，
业务规则尽量下沉到数据库（约束 / 触发器 / 存储过程），
数据库是主角，应用只是它的遥控器。

### 3.3 设计要点

- **数据库是主角，应用只是遥控器** —— 业务规则尽量下沉为约束、触发器与存储过程；
  应用层刻意做薄：无分层架构、无 Repository 抽象、不引入重型 ORM。
- **单据驱动** —— 三类单据（采购申请单 / 销售单 / 预订单）都采用「头 + 行」两级结构，
  明细行逐条留痕、可回溯；**每张单据都有单号**，卖货与预订的单据会交给顾客一份。
- **库存只维护计数** —— 保留「在架总量」与「已订量」两个计数，
  可售量由二者**派生**而不单独存列，从根上消除两个数对不上的可能。
- **线上预订只锁货** —— 预订单不含任何金额字段，价格与折扣等到到店结算时才确定；
  预订阶段不动钱、不动积分。
- **资金逐笔留痕** —— 每笔资金变动都记录金额、原因、时间与**变动前后余额**，
  账面可以随时复查。

### 3.4 技术选型

| 层 | 选型 | 说明 |
|---|---|---|
| 数据库引擎 | SQL Server Express 2022 | 主战场 |
| 数据库工具 | SSMS | 建库、调试、执行计划 |
| 应用层 | Python 3 + Flask | 刻意保持薄，无 ORM 抽象 |
| 数据库驱动 | pyodbc + ODBC Driver 18 | 直接执行 T-SQL |
| 模板引擎 | Jinja2 | 服务端渲染，页面简单 |
| 前端样式 | 单文件 CSS，无构建工具 | 简洁优先 |

小组对 C/C++ 最熟，Web 层不是学习目标。Flask 代码量最小，每条 SQL 都直接可见，
最贴合「学 SQL」的诉求。
