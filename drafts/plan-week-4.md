## 2. 已完成的 SQL 工作

### 2.1 多表查询：`db/query.sql`

脚本共整理了 7 组业务查询，并为每组查询写明业务问题：

1. 销售单、销售明细、商品和会员归属；
2. 所有商品的销售数量和原始销售金额，包括没有销售记录的商品；
3. 库存、已订数量和可售数量；
4. 销量至少为 2 件的商品；
5. 消费金额高于会员平均消费的会员；
6. 采购单、供应商、采购明细和供应商报价；
7. 销售明细的累计退货数量和剩余可退数量。

查询覆盖了销售、商品、会员、预订、采购、供应商报价和退货等对象，使用了 `LEFT JOIN`、聚合函数、`GROUP BY`、`HAVING` 和子查询。

重点说明：查询无销售商品时使用 `LEFT JOIN`，否则 `INNER JOIN` 会把没有销售明细的商品过滤掉；查询非会员销售时也需要保留销售单，因此会员关联不能简单改成内连接。

主要复核结果：

- Q1 返回 4 行销售明细；
- Q2 返回 4 个商品，商品 1 销量为 5、金额为 195.00，商品 4 销量为 0；
- Q3 返回 4 行库存状态，商品 1 可售数量为 0；
- Q4 返回商品 1 和商品 2；
- Q5 在当前样例数据下为空结果，原因是只有一个会员有销售记录；
- Q6 返回 5 行采购明细；
- Q7 返回 4 行销售明细，其中 2 行存在退货。

第一次执行时发现 Q3 的 `@AsOf` 变量跨过 `GO` 后失效，按 SQL Server 的批次作用域规则在对应批次重新声明变量，修正后退出码为 `0`。

### 2.3 完整性约束：`db/constraint.sql`

本周没有重复创建 Week 3 已有的主键、外键、唯一、默认值和单行 `CHECK` 约束，主要补充了跨行会员卡档位关系检查。

新增的 `dbo.tr_card_type_cross_row` 触发器验证：

- 金卡办卡费必须严格高于银卡；
- 金卡折扣率不得高于银卡。

跨行关系非法时返回自定义错误码 `51025`，测试事务回滚。

已验证的合法正例和非法反例：

| 用例 | 结果 |
|---|---|
| 金卡办卡费增加 1.00 | 合法，通过后回滚 |
| 金卡办卡费改为不高于银卡 | 被触发器拒绝，错误码 `51025`，回滚 |
| 已订数量超过库存 | `547`，回滚 |
| 销售明细数量为非正数 | `547`，回滚 |
| 未知商品外键 | `547`，回滚 |
| 重复销售单号 | `2627`，回滚 |
| 资金流水余额不平 | `547`，回滚 |

第一次数量反例测试先触发了销售明细唯一约束，之后改用该销售单中尚未出现的 `goods_id = 4`，使测试实际命中 `CK_sale_item_quantity`。

### 2.4 角色权限：`db/role.sql`

创建并测试了三个店内数据库角色：

- `bookstore_manager`：店长；
- `bookstore_cashier`：收银员；
- `bookstore_inventory`：库存管理员。

顾客不创建员工式数据库角色，按正式角色文档作为业务层主体，由应用层或业务 SQL 使用手机号、预订码等业务凭证验证归属。

已验证的正常操作和越权操作：

| 角色 | 正常操作 | 越权操作 | 结果 |
|---|---|---|---|
| 收银员 | 读取商品成功 | 修改商品价格 | 失败，错误码 `229` |
| 库存管理员 | 新增供应商报价成功并回滚 | 插入销售单 | 失败，错误码 `229` |
| 店长 | 读取资金流水成功 | 修改已完成销售单 | 失败，错误码 `229` |

脚本没有授予 `db_owner`、`CONTROL` 或 `ALTER` 等超范围权限。
