# 问题记录：商品"必要的删除"未实现（三无商品物理删除）

- **状态**：口径已定（2026-11-04，User 决策）→ **待实现（作者）**
- **提出**：非作者复核（Web 审查，2026-11-05）
- **依据**：第 7—9 周任务 5「商品、库存、订单和订单明细的查询、增加、修改和**必要的删除**」
- **影响面**：商品档案管理（库管 / 店长）；不涉及已成交单据
- **相关文件**：`app/operations.py`、`app/templates/operations.html`、`db/operations-entry.sql`、`db/role.sql`、`docs/reports/report-web-v1.0.md`

---

## 1. 现状与问题

| 项 | 现状 |
|---|---|
| 商品删除入口 | **无**（`/goods` 只有"新建/编辑资料"） |
| 数据库权限 | 库管角色只有 `goods` 的 `SELECT/INSERT`，无 `DELETE` |
| 业务规则 | 设计口径为"默认下架保留引用"（`plan-web-development.md:165`） |
| 后果 | 误建档案（名称打错、编码选错）只能下架，永久留在列表；评审追问"删除在哪"时无法回答 |

课程要求"必要的删除"，落到商品上最典型的就是**建错的档案**——这是"必要"的，不是可选项。

---

## 2. 决策（2026-11-04）

> **支持物理删除"三无"商品。**

同时确认另一条口径（问题二）：**成交后的销售单与明细冻结锁定，不允许修改/删除**；纠正只能走退货冲销。

---

## 3. "三无"的判定（实现必须逐条校验）

| # | 条件 | 判定方式 |
|---|---|---|
| 1 | **无库存** | `goods.stock_total = 0 AND goods.reserved_qty = 0` |
| 2 | **无任何引用** | 下列 5 张表均无该 `goods_id`：`sale_item`、`purchase_request_item`、`reservation_item`、`stock_movement`、`supplier_quote` |
| 3 | **未上架** | `goods.on_shelf = 0`（须先下架才能删） |

三条**同时满足**才允许删除；任一不满足 → 拒绝并说明原因（409）。

> 说明：`goods.price` 是否为空不参与判定——已定价但从未上架、从未被引用的档案也属"三无"，可删。

---

## 4. 实现要求（建议）

| 层 | 要做的事 |
|---|---|
| 数据库 | 新增 `api.usp_goods_delete`：在一个事务内做三条校验 → `DELETE dbo.goods WHERE id=@id`；返回受影响行数；校验失败抛业务错误码 |
| 授权 | 仅授予**库管**执行（`bookstore_app_inventory`）；`bookstore_app_manager` 不授予（定价权与删除权分离） |
| 服务 | `OperationsService.write(actor,'goods_delete',…)`，沿用现有动作白名单与请求幂等 |
| 页面 | `/goods` 列表每行增加"删除档案"按钮（仅库管、仅满足三无时可见），二次确认；删除后回列表并提示 |
| 错误 | 409 + 可读原因："该商品有库存，不能删除""该商品已被单据引用，不能删除""请先下架再删除" |
| 留痕 | 物理删除无业务留痕；**至少写请求日志**（`action=goods_delete, goods_id, actor`） |
| 文档 | 数据字典无需改（无结构变更）；`web-operation-manual.md` 增加"删除误建档案"步骤 |

**不需要迁移**：不新增表/列/约束，只加过程与授权。

## 5. 验收用例

| 编号 | 前置 | 操作 | 预期 |
|---|---|---|---|
| G-01 | 新建商品（0 库存、未上架、无引用） | 库管删除 | 删除成功，列表与 `goods` 均消失 |

| G-07 | 店长账号调用删除接口 | 直接 POST | 403（未授权） |
| G-08 | 删除后重新用同一编码建档 | 新建 | 成功（唯一索引已释放） |

## 6. 风险与边界

| 风险 | 处理 |
|---|---|
| 误删有历史价值的档案 | 三条校验拦住"有引用/有库存"；仅允许"从未发生过业务"的档案 |
| 删除后无法追溯 | 物理删除天然不可追溯；已在请求日志留 `goods_id` 与操作人 |
| 与"不物理删除"原则冲突 | 原则针对**业务事实**（单据/流水）；档案层允许清理未使用数据，边界写入手册与报告 |
| 教师追问"为什么别的对象不能删" | 统一口径：单据与流水是事实，改/删用冲销；档案未使用可删 |
