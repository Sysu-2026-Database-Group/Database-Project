# 拾光书店 · 角色与职能清单

> **性质**：正式文档（已敲定）。
> **用途**：第 4 周权限设计（授权）的依据 —— 每个角色的「能做 / 不能做」都要能直接落成授权规则。

---

## 1 主体总览

| 类别 | 主体 | 守哪条线 |
|---|---|---|
| 店内角色 | **库存管理员** | 货 |
| 店内角色 | **收银员** | 钱与顾客 |
| 店内角色 | **店长** | 决策与账 |
| 外部主体 | **顾客**（含会员 / 非会员） | —— |

- **人数**：店长 1、收银员 2、库存管理员 1 = **4 人**（人数不进数据库设计）
- **不设 / 不纳入**的主体（**系统管理员**、**会员**、**供应商**）**见 §6** —— 理由不在此重复。

## 3 逐角色说明

### 3.1 库存管理员 —— 货的唯一经手人

| | 内容 |
|---|---|
| **能做** | 商品建档（登记商品本身的信息，**售价留空**）、维护多家供应商的当前报价并提交采购申请（指定一家）、收货入库、报损、退货回收入库 |
| **不能做** | 收款 / 退款、定价 / 改价、直接改库存数量 |
| **能看** | 商品**采购价格**、商品**当前售价**、库存数量、**库存的变动历史**（B12 的来龙去脉） |
| **不能看** | 全店经营账（营收、盈亏） |

> 为什么能看到采购价：申请是他写的，供应商也是他选的。
> 为什么能看到售价：售价不是隐私信息，**只是他无权修改**。

### 3.2 收银员 —— 钱与顾客的唯一交接口

| | 内容 |
|---|---|
| **能做** | 门店开单结算收款、线上预订到店自提的核销与结算、受理退货退款、办理会员（开卡 / 登记，**含收取办卡费**）、查自己经手的单 |
| **不能做** | 定价 / 改价、改库存数量 |
| **能看** | 库存数量（含**可售量 / 已订量 / 在架总量** —— **只能看**，结算要用的是可售量）、自己经手的单据 |
| **不能看** | 全店经营账 |

### 3.3 店长 —— 唯一的决策者与监督者

| | 内容 |
|---|---|
| **能做** | 审批采购申请、收货后支付采购款、定价 / 调价（**参考各供应商的报价**）、**上架 / 下架商品**、维护银卡与金卡的当前办卡费和折扣率、维护员工账号、**对经营盈亏负责**（查看**收入 / 支出 / 经营盈亏 / 现金余额**）、**登记注资 / 提现**、查库存变动历史 |
| **不能做** | 直接改库存数量、修改已完成单据的**内容**（快照不回改） |
| **能看** | **全店经营账**（收入 / 支出 / 经营盈亏 / 现金余额）、库存与变动历史、采购、销售、预订、退货单据、会员信息 |
| **不能看** | ——（经营信息对他**全部开放**） |

> 店长支付采购款及注资、提现会产生资金流水；审批与付款是不同动作，分别留痕。

### 3.4 顾客 —— 外部主体

| | 内容 |
|---|---|
| **能做** | 选货购买、线上预订；凭手机号与预定码查询或取消自己的预订；验证归属后查询自己的会员信息与销售单 |
| **不能做** | 操作后台、看别人的数据 |
| **能看** | **已上架商品**的公开信息（名称 / 展示信息 / 售价 / 有没有货）、经凭证核对后自己的预订、会员销售单、退货单及积分；非会员销售单由收银员凭单号核对 |
| **不能看** | **别人的**数据、店里内部的信息（采购价 / 库存明细 / 经营账） |

## 4 五条横切约束（对全部角色生效）

1. **谁都不能直接改「算出来的数」**（库存数量、账面金额、积分余额……）——
   这些数只能因为「发生了一笔业务」而改变。
2. **「能看」不等于「能改」** —— 两者权限粒度不同，授权时必须分开写。
3. **一人一角色，不兼职** —— 需要人手就"某角色多配几人"或增员。
4. **操作人留痕** —— 每个"动数据 / 改基础数据"的动作都要记下**操作人 + 时刻**（**可溯源**）。
   只查询的动作不留痕；**不做**字段级变更历史、**不做**前后值快照；
   **记的是"做这件事的人"（业务动作者），不是"谁在系统里点了按钮"** ——
   如销售收款记当班收银员、退货引起的积分回滚记该次退货的受理人、采购付款记店长。
   **没有人类动作者的自动动作不设留痕列**（如预订到期只改单的状态，不记人）——
   这样留痕字段永远指向一位真实员工。
   店内动作使用员工登录身份；顾客预订用手机号与预定码识别，会员自助查询须另行验证归属。**手机号本身不是授权凭证**，第 4 周须设计验证机制。
   （**本条是唯一口径** —— `docs/spec-businesses.md` 的 R-22 指向此处，不复述。）
5. **不得修改已完成单据的「内容」** —— 开出去的单据（采购申请单 / 销售单 / 预订单）一旦成立就是记录：
   金额、折扣、数量等**快照不许回改**；要纠正只能开新单，或按业务规则冲销。
   注意：**状态迁移不算"改内容"**（例如退货把销售单从"已付"变成"部分退款"）。

> 第 4 周做权限设计时，**①②③⑤** 决定了「越权应当失败」的反例怎么构造；
> **④** 决定了「操作留痕」要记在哪些动作上。

---

## 5 会员系统归谁管

- **会员人**（开卡 / 登记、改联系方式、查积分）→ **收银员** —— 职能本体见 §3.2「办理会员」。
- **会员卡档位参数**（当前办卡费、折扣率）→ 店长维护，见 B9 会员卡档位配置、R-17；收银员按办理当时的配置收费，结算按当时配置计价。
- **积分换算与抵扣规则** → `spec-businesses.md` R-7；本阶段作为业务规定，不由经营角色在线修改。
- **会员系统的技术维护**（改表结构 / 改程序 / 修数据）→ **项目组（我们）** —— 不是经营角色，不进清单。

---

## 6 不设的角色 / 不纳入的主体

| 对象 | 结论 | 理由 |
|---|---|---|
| 系统管理员 | **不设置** | 不产生任何经营数据；账号由店长维护，店长的初始账号在创店时预置 |
| 会员 | 不单列 | 是顾客的一种身份 / 权益 |
| 供应商 | 不列为系统角色 | 在店外、不登录系统；其身份与报价仍进入数据库，并参与采购 |

> 保留的概念区分：**经营角色 ≠ 权限主体**。经营角色是"会动经营数据的人"；
> 权限主体是能通过登录或业务凭证获得限定操作权的人；顾客不必为预订建立员工式账号。系统管理员不属于经营角色。
