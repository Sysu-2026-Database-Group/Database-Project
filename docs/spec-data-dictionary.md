### 0.2 命名风格（全表贯彻）

| 对象 | 规则 | 例 |
|---|---|---|
| 表名 | 使用英文小写字母，以下划线分词，采用**单数**形式 | `purchase_request` |
| 字段名 | 同上 | `stock_total` |
| 主键 | 代理键统一叫 `id`；**用业务键做主键的就用键自己的名字** | `goods.id`、`book.isbn`、`member.phone` |
| 外键 | `<被引用表名>_id`；被引用表用业务键做主键时写 `<表名>_<键名>` | `sale_id`、`member_phone` |
| 时刻 | 后缀 `_at` | `created_at`、`sold_at` |
| 人 | 后缀 `_by` | `changed_by`、`cashier_by`、`reported_by` |
| 金额 | 后缀 `_amount`；固定收费额用 `_fee` | `refund_amount`、`card_fee` |

### 0.3 类型口径

| 语义 | 类型 | 理由 |
|---|---|---|
| 金额（售价 / 实付 / 退款 / 办卡费 / 进价） | `DECIMAL(10,2)` | **绝不用浮点** —— 钱的比较与求和不能有误差 |
| 资金总额（收付前 / 后） | `DECIMAL(12,2)` | 同为定点；位数放宽一档 |
| 数量、积分 | `INT` | 积分**可以为负**（R-25 退货回滚时） |
| 折扣率 / 折扣（0–1） | `DECIMAL(3,2)` | 定点；不用浮点 |
| 是 / 否 | `BIT` | R-1 明说"上架是布尔"；不拿字符存 Y/N |
| 时刻 | `DATETIME2` | 留痕要精确到时刻 |
| 中文文本（名称 / 说明 / 姓名） | `NVARCHAR(n)` | 长度按实际给 |
| 编码类（手机号、ISBN、内部编码、单号 / 预定码、账号） | `VARCHAR(n)` | **绝不参与算术**，用字符防前导零被吃掉 |

> **「域」不是「类型」，也不是「数据结构」** ——
> **类型 / 长度精度**管"**怎么存**"，**域**管"**什么值算合法**"，**表怎么组织**（关系模式）是子任务 1 的事。
> 例：`member.points_balance` 的类型为 `INT`，域要求是“**整数，可为负，且须等于该会员积分流水之和**”（R-25）——
> "可为负""须等于流水之和"**只有域能表达**；域写成"数字"等于没写（`task-week-2.md` 验收第 4 条的判不过情形）。
> 域有三种写法：**枚举**（列全取值，如 `购入 / 卖出 / 退货 / 损坏`）、**区间**（给端点，如 `0 < 折扣率 ≤ 1`）、
> **由别的表定义**（即**外键** —— 合法值就是被引用属性的取值集合，如 `sale.member_phone` 的域 = `member.phone` 的取值集合）。

**全表通用约定**：

1. **主键默认 `id BIGINT IDENTITY`**（自增）；业务键另加唯一约束。
   **业务键做主键**的有：`book`（ISBN）、`toy`（内部编码）、`member`（手机号）、`employee`（手机号 = 账号）、
   `supplier_quote`（"供应商 + 商品"复合）、`card_type`（档位名）。
   —— 判据：**这个键"定了以后还会不会改"**。
2. **留痕一律成对**：`_by VARCHAR(11)`（指向 `employee.phone`）+ `_at DATETIME2`。
   **记的是"做这件事的人"（业务动作者），不是"谁在系统里点了按钮"** —— 所以每一笔留痕都能落到一位**真实员工**上
   （销售收款记该单的收银员、退货引起的积分回滚记该次退货的受理人、采购付款记店长）。
   **没有人类动作者的自动动作不设留痕列**（如预订到期只改 `reservation.status`，不记人）——
   这样留痕列**永远挂得上员工外键**，不必也不可能出现 `「系统」` 这类非员工值（R-22、`spec-roles.md` §4 第 4 条）。
3. 不用 `NULL` 表达"0"或"没有"以外的语义；**该为空的地方都在「域」里写明"何时为空"**。
4. 时刻默认值写 `SYSDATETIME()`；金额类不给默认值。
5. **「域」写 `—` 只限三类**：时刻列（合法日期时间）、主键列（自增正整数 / 业务键自身取值）、
   外键列（＝被引用表主键的取值集合）。其余列**一律写明域**。
6. 每个字段都服务明确的业务或规定（`B-*` / `R-*` / `A-*`）—— **"以后可能要用"的字段一个都没有**。
   > **「含义」里挂 `A-*` / `R-*` 是我们的做法，不是官方要求**（官方只要求写"字段的含义"，
   > 并要求设计者"**能解释**"每字段的来历）—— 我们把它落成"**评审时一查就有**"。
   > **代理键 `id` 这类列不挂**：它不来自边界清单，没有可挂的对象；它用于唯一标识一行，
   > 选用它的理由由 §0.4 的取码判据交代。

### 0.4 主键与候选码一览（19 张）

| 表 | 主键 | 候选码（其他能唯一标识的） | 为何这样选 |
|---|---|---|---|
| `goods` | `id`（代理） | 业务候选码**无** | 名称会重；`book_isbn` / `toy_code` 必有一个为空，**含空值的属性组不能唯一标识** |
| `book` | **`isbn`** | ——（即主键） | ISBN 是国家标准，认书就认它 |
| `toy` | **`inner_code`** | ——（即主键） | 内部编码编好就贴在货上 |
| `supplier` | `id`（代理） | `name` | 名称可以改 → 做唯一约束 |
| `supplier_quote` | **`supplier_id` + `goods_id`** | ——（即主键） | 多对多关系，本身无独立身份；复合码极小 |
| `stock_movement` | `id`（代理） | 无 | 一件商品有很多次变动 |
| `purchase_request` | `id`（代理） | `no` 单号 | 单号是"对外标识"（R-19），生成规则可能变 |
| `purchase_request_item` | `id`（代理） | `request_id` + `goods_id` | 一张单里同一商品只出现一次 → 唯一约束 |
| `sale` | `id`（代理） | `no` 单号 | 同上（顾客凭它认单，R-20） |
| `sale_item` | `id`（代理） | `sale_id` + `goods_id` | 同上 |
| `reservation` | `id`（代理） | `code` 预定码 | 预定码不做主键 |
| `reservation_item` | `id`（代理） | `reservation_id` + `goods_id` | 同上 |
| `goods_return` | `id`（代理） | `no` 退货单号 | 同一原销售单可多次退货；单号可供外部核对 |
| `goods_return_item` | `id`（代理） | `return_id` + `sale_item_id` | 同一退货单中原销售行只出现一次 |
| `card_type` | **`level`** | ——（即主键） | 当前银卡、金卡两档以档位名标识，不另加代理键 |
| `member` | **`phone`** | ——（即主键） | 手机号是唯一凭证，认人就认它 |
| `point_movement` | `id`（代理） | 无 | 一位会员有很多笔 |
| `fund_flow` | `id`（代理） | 无 | 很多笔收付 |
| `employee` | **`phone`** | ——（即主键） | 账号就是手机号，认人也认它 |

> **定义链（教材口径）**：**超码** = 能唯一标识一行的任意属性组；**候选码** = **极小的**超码
> （去掉其中任一属性后就不再唯一）；**主码** = 从候选码里**选出来用**的那一个
> （**一个表只有一个主码，但可以有多个候选码**）。
> ⚠️ **所以"业务候选码：无"指的是"业务属性里找不出第二个"** —— 用代理键 `id` 的表，
> **`id` 本身就是候选码**（具有唯一性和极小性，只是人为加的）。
> **可空的列不能单独当候选码** —— 唯一性没法保证（多行都为空时就不唯一了）——
> 这正是 `goods` 只能靠代理键的原因。

### 1.2 `book` 图书 —— 一行 = 一本图书

| `discount_rate` | `DECIMAL(3,2)` | — | 否 | `1.00` | 0 < 值 ≤ 1；**非会员按 `1.00` 记** | 成交时从 `card_type` 读取并保存的折扣率快照（R-8、R-17） |

### 4.1 `fund_flow` 资金流水 —— 一行 = 一笔收或付

| 字段名 | 类型 | 键 | 空 | 默认 | 域 | 含义 |
|---|---|---|---|---|---|---|
| `id` | `BIGINT` | 主键 | 否 | 自增 | — | 流水标识 |
| `amount` | `DECIMAL(10,2)` | — | 否 | — | > 0（**方向另记，不靠正负**） | 这笔钱的金额 |
| `direction` | `NVARCHAR(2)` | — | 否 | — | 枚举：**收 / 付** | 钱进来还是出去（R-15 靠它区分收支） |
| `reason_type` | `NVARCHAR(10)` | — | 否 | — | 枚举：**销售收款 / 采购付款 / 退货退款 / 办卡费 / 注资 / 提现** | 事由类别（A17） |
| `sale_id` | `BIGINT` | 外键 → `sale.id` | **是** | — | **销售收款 / 退货退款时非空** | 收款的销售单；退款时为退货单指向的原销售单 |
| `return_id` | `BIGINT` | 外键 → `goods_return.id` | **是** | — | 仅退货退款时非空，且与 `sale_id` 指向同一原单 | 本次退款所对应的退货单 |
| `request_id` | `BIGINT` | 外键 → `purchase_request.id` | **是** | — | **只有"采购付款"非空** | 挂在哪张**采购单**上 |
| `member_phone` | `VARCHAR(11)` | 外键 → `member.phone` | **是** | — | **只有"办卡费"非空** | 办的是哪位会员的卡（B8） |
| `fund_before` | `DECIMAL(12,2)` | — | 否 | — | ≥ 0 | 收付**前**的资金总额 |
| `fund_after` | `DECIMAL(12,2)` | — | 否 | — | = `fund_before` ± `amount` | 收付**后**的资金总额（**= 店内资金总额**，A17、R-15） |
| `recorded_by` | `VARCHAR(11)` | 外键 → `employee.phone` | 否 | — | — | 登记人 —— **做这笔业务的人**（R-22 §4） |
| `recorded_at` | `DATETIME2` | — | 否 | `SYSDATETIME()` | — | 收付时刻 |

> **事由用四个可空外键挂**（R-15「经营盈亏靠事由筛」，所以事由必须挂得下去）：
> **注资 / 提现时四个全空**；销售收款→`sale_id`，采购付款→`request_id`，办卡费→`member_phone`，退货退款→`sale_id` 与 `return_id` 同时非空，且两者必须指向同一原销售单。`reason_type` 仍保留 —— A17 要求把事由记下来，
> 且 R-15 按它筛"经营 / 非经营"，**显式可读的事由比从空值推断可靠**。
> 退货退款的 `amount` 还必须等于所指退货单的 `refund_amount`；这是跨表等式，普通单行 `CHECK` 无法保证。
> **不用"单号弱引用"的原因**：弱引用指向一张不存在的单也存得下去，违背 R-15「事由要挂得下去」。
> **`recorded_by` 记"做这笔业务的人"**（不是"谁点了按钮"）：销售收款 → 该单的收银员；
> 退货退款 → 该次退货的受理人；采购付款 / 注资 / 提现 → 店长；办卡费 → 开卡的收银员。
> —— 所以它**永远是一位真实员工**，挂得上 `employee.phone` 的外键。
