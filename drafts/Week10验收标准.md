# 第 10 周验收标准（Week10）

- 日期：2026-11-16
- 定位：用于验收组员第 10 周交付，不替代任务说明，也不规定实现细节
- 依据：`homework/第10周任务讲解.md`、`docs/tasks/task-week-10.md`
- 原则：**验收对象看“课程要求的接口与行为是否可用”**；额外对象、额外参数不直接扣分，但不能替代核心接口

## 1. 验收对象

| 类别 | 必须存在 | 说明 |
|---|---|---|
| 核心存储过程 | 2 个 | 销售统计、库存调整 |
| 核心函数 | 3 个 | 补货量、销售汇总 TVF、折扣计算 |
| 复用项 | 1 个 | 订单完成复用 v1.0 的 `api.usp_sale_create`，不要求新写 |
| 核心产物 | 4 项 | `procedure.sql`、`function.sql`、一份测试脚本、验收结果报告 |

> 允许额外增加包装过程或辅助函数；额外对象不能替代上述核心对象，也不能导致核心对象无法独立调用。

## 2. 硬性验收项

| # | 验收项 | 通过标准 | 判不过的典型情形 |
|---:|---|---|---|
| A1 | 两份 SQL 交付 | `procedure.sql` 含核心存储过程；`function.sql` 含核心函数；可在隔离库创建 | 只有代码片段、无法创建、缺少核心对象 |
| A2 | 两个核心过程可调用 | 销售统计、库存调整均可带参数重复调用；参数、返回、错误有说明 | 核心过程不存在，只有内部过程或包装过程 |
| A3 | 三个核心函数可调用 | 补货量、销售汇总 TVF、折扣计算均可独立调用 | 函数数不足，或只有内部辅助函数 |
| A4 | 销售统计 | 输入起止日期；含结束日；订单数不重复；空区间返回 0 值/空明细；非法日期报错 | 日期不含结束日、订单数重复、空区间报错 |
| A5 | 库存调整 | **只凭“商品、数量、原因、员工”四个输入可独立调用**；成功改库存并写流水；商品不存在/数量 0/库存不足/原因缺失时拒绝；失败无残留 | 必须由调用方先开事务/提供来源 ID 才能调用；核心四参数入口不存在 |
| A6 | 补货量 | 输入商品与目标量；按可售量计算；达到目标返回 0；商品不存在/空值/负目标有明确处理；不为负 | 返回负数；对不存在商品静默返回 0；无法区分“无商品”与“无需补货” |
| A7 | 销售汇总 TVF | 输入日期范围；返回商品编号、名称、销量、销售额、订单数；可在 `SELECT` 中调用；空区间返回空集 | 只能通过过程调用；空区间报错；列缺失 |
| A8 | 折扣计算 | 由数据库函数根据**会员身份/金额/分类**得出折扣率与折扣金额；非法金额/折扣报错；成交仍写快照 | 函数只接收“金额 + 倍率”，折扣率仍由应用层决定；历史快照被重算 |
| A9 | 输入与错误处理 | 空值、错误编号、错误日期、非法数量、非法折扣均有明确错误码或可识别返回；不暴露 SQL/表名 | 非法输入落库、返回 NULL 无说明、错误页泄露内部信息 |
| A10 | 订单完成复用 | 仍走 `usp_sale_create`（或现有等效提交过程）；库存不足、重复提交、失败回滚不退化 | 新写第二套订单完成逻辑；重复提交产生两单 |
| A11 | 页面只调用 | 页面经 DAO 调用过程/函数，不保留第二套统计、折扣、库存逻辑 | 页面/服务层仍拼 SQL 或重复计算 |
| A12 | 测试覆盖 | 覆盖补货、订单完成、库存调整、折扣；覆盖正常、空值、错误编号、错误日期、非法数量、非法折扣、重复调用 | 只测成功路径；没有反例 |
| A13 | 结果记录 | 每条用例有输入参数、预期、实际、成功/错误信息、未写入验证 | 只有截图或 PASS，没有实际值与失败后状态 |
| A14 | 回归 | 现有 119 项测试仍通过；新增用例有独立结果 | 新对象破坏销售/采购/退货链路 |

## 3. 对象级核对表

| 对象 | 最低输入 | 最低输出 | 必须拒绝/处理 |
|---|---|---|---|
| 销售统计过程 | 开始日期、结束日期 | 订单数、销售数量、销售金额、商品明细 | 空日期、起 > 止、无销售 |
| 库存调整过程 | 商品、数量、原因、员工 | 新库存、流水编号/记录 | 商品不存在、数量 0、库存不足、原因缺失 |
| 补货量函数 | 商品、目标量 | 非负补货量 | 商品不存在、目标为负/空 |
| 销售汇总 TVF | 开始日期、结束日期 | 商品编号、名称、销量、销售额、订单数 | 空范围（返回空集） |
| 折扣函数 | 会员身份、金额/分类 | 折扣率、折扣金额 | 非法金额、非法折扣 |

> 附加参数（如员工、会话、来源单据）可以有，但**不能成为核心四参数调用的门槛**；若必须附加，需提供满足课程签名的包装入口。

## 4. 测试覆盖矩阵

| 用例组 | 必测 |
|---|---|
| 销售统计 | 多日、单日、结束日当天、无销售、起 > 止、空日期 |
| 库存调整 | 正常减少、商品不存在、数量 0、负数、超库存、原因缺失、失败回滚 |
| 补货 | 低于目标、等于目标、高于目标、未知商品、空值、负目标 |
| 折扣 | 非会员、银卡、金卡、金额边界、非法折扣、成交快照 |
| 订单完成 | 正常成交、库存不足、重复提交、失败回滚 |
| 重复调用 | 统计稳定；库存调整的“累计 vs 拒绝”语义明确 |
| 权限 | 库管可调整、收银不可调整；统计只店长；无权限拒绝 |

## 5. 证据要求

每条用例必须保存：

```text
输入参数
预期结果
实际结果
成功结果或错误码/提示
是否写入（失败后库存、流水、单据是否原样）
```

验收时逐项填写：

| 用例 | 输入 | 预期 | 实际 | 结论（通过/失败/待验证） | 证据 |
|---|---|---|---|---|---|

## 6. 判定规则

| 判定 | 含义 |
|---|---|
| 通过 | 硬性项满足，且证据可复核 |
| 失败 | 有复现步骤与实际结果，不能以“计划中”代替 |
| 待验证 | 未执行或环境不齐；不能计入通过 |
| 部分通过 | 仅限非核心项；A1—A8 任一失败不得宣布本周完成 |

## 7. 当前实现需重点核对（不预判结论）

组员当前交付中观察到以下差异，验收时逐项确认：

1. 过程数为 3 个（`usp_adjust_stock`、`usp_replenishment`、`usp_sales_statistics`），而课程核心要求是 2 个；确认额外过程是否只是包装。
2. `usp_adjust_stock` 有 8 个参数并要求调用方事务/来源 ID；确认是否存在满足“商品、数量、原因、员工”四输入的独立入口（A5）。
3. `fn_sale_discount` 只接收 `(subtotal, rate)`；确认“会员身份 → 折扣率”是否另有数据库函数（A8）。
4. 补货函数对未知商品返回 `NULL`；确认调用入口是否给出明确错误。
5. 测试记录称 123 项通过（119 + 4 个成交直调）；独立复跑确认是否 0 失败/0 跳过。
