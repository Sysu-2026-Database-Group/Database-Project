## 0 阅读约定与术语

**阅读约定**

- 提到业务一律「**编号 + 名称**」并写（例：「B6 线上预订与取消」），不裸用编号。
- **业务 = 有明确角色执行的一条动作链**；其余一切（状态表达、快照、展示口径、对账等式……）
  都是**规定**，附着在已有业务上，**不因此新增业务条目**。
- 本文的**规定即为定案**，不再另设"定案记录"节。
- 本组的实施批次（第一批 / 第二批 / 第三批）属于排期，不写进本文，见 `drafts/plan-week-1.md` §4.4。

**术语**（本文与 `docs/spec-scenario.md`、`docs/spec-roles.md` 共用同一套）

| 术语 | 含义 |
|---|---|
| **在架总量** | 货架上真实有多少 —— **含已被订走、还没取走的货**；也是**与"变动累加"对账的基准** |
| **已订量** | 已被订走、等待取货的数量 |
| **可售量** | `在架总量 − 已订量` —— 还没有主、可以卖的货 |
| **上架** | 一个布尔值，表达**店长的意思**：这个商品允不允许卖 |
| **能不能卖** | `上架 且 可售量 > 0` |
| **单据** | 三种：**采购申请单**（买货）· **销售单**（卖货，即官方所说的"订单 / 订单明细"）· **预订单**（线上预订） |

## 1 业务清单（15 条）

> **原 B4「库存盘点」已取消** —— 本项目的数据是**虚拟的**：**数据库记多少，实际就是多少**，
> 不存在"账实核对"的对象（盘点是为**真实门店**准备的业务）。
> 因此库存只会因**发生业务**而变化：进货 · 卖出 · 退货 · 报损 —— **没有人能"手调"库存**。
> **编号 B4 留空、不重排**（B5 起保持原样，`R-*` 与边界清单的引用都不受影响）。

### 1.1 货线（库存管理员主导）

| # | 业务 | 一串动作（谁做什么） | 类型 |
|---|---|---|---|
| B1 | **商品建档、定价与上下架** | 库管登记商品（**售价留空**）并**上报各供应商的当前报价** → 商品**未上架**（卖不出去）→ 店长参考报价**定价**并**置为上架** → 商品可以卖；店长此后可调价，也可**下架** | 改基础数据 |
| B2 | **商品采购** | 库管提交申请（**带上向多家供应商询得的报价**，并指定其中一家）→ 店长审批 → 到货**按实收数量**收货入库 → **店长付款** | 动数据 |
| B3 | **商品报损** | 库管登记报损 → 库存减少 | 动数据 |

> **B1 的交接（库管 → 店长）**：**不需要另写"定价申请单"** ——
> ① 建档时**上报报价就是交接信号**；② 商品建档后处于「**未上架**」，店长打开「未上架清单」即可看到；
> ③ 多一张申请单只会把建档内容（商品 + 报价）重复一遍。
> **店长的作用**就体现在**没有他定价，商品卖不出去** —— 顾客看得见商品、库管看得见库存，但收银台结不了账。

> **报价**：**先于采购**发生，由库管询价时向**多家供应商**问价，**随采购申请一起上报**（不是只记最后选中的那家）。
> 用途：① **定价的依据**（新商品从未采购过，报价是唯一的参考）；② **选供应商的依据**。
> **呈现方式**：按**供应商列当前报价** —— **不记历史**、不做"最近一次 / 区间"；新报价直接覆盖旧报价。

### 1.2 钱与顾客线（收银员主导）

| # | 业务 | 一串动作（谁做什么） | 类型 |
|---|---|---|---|
| B5 | **门店销售** | 顾客选货 → 收银员结算收款 → **生成销售单**（头 + 行）、库存减少、会员权益生效 | 动数据 |
| B6 | **线上预订与取消** | 顾客线上下单（**登记手机号**）→ 系统发**预定码**（唯一凭证）→ **锁定商品**（不收款、不动价）；顾客可自行**取消**，收银员也可代取消 → 商品释放 | 动数据 |
| B7 | **到店取货** | 顾客报**手机号 + 预定码** → 收银员核对预订并结算 → 收款、**生成销售单**（头 + 行）、商品交付（库存离店） | 动数据 |
| B8 | **商品退货** | 顾客请求并**出示单号** → 收银员**凭单号**核销原单、**退款（只退实付）**、**回滚该次获得的积分** → 库管回收入库 | 动数据 |
| B9 | **会员办理** | 顾客申请 → 收银员开卡登记并**收取办卡费**（会员身份在结算时生效） | 动数据 |

> **线上预订怎么"冻结"**：**不打任何标记，也没有"冻结 / 解冻"这个动作** ——
> 冻结是「**已订量**」上升的**自然结果**：
>
> ```text
> 预订  →  已订量 +N   →  可售量 = 在架总量 − 已订量   →  −N
>                        →  可售量归 0 时，这个种类就卖不出去、也订不了了
> ```
>
> 1. **货还在架上** —— 在架总量不变，所以**对账基准不变**；
> 2. **不需要知道是哪一册** —— 按"不追踪到单件"的粒度，被订走的是「这个种类的 N 个名额」；
> 3. **取消 / 过期自动解冻** —— 已订量 −N、可售量回补，商品自动又能卖。

### 1.3 决策线（店长主导）

| # | 业务 | 一串动作（谁做什么） | 类型 |
|---|---|---|---|
| B10 | **会员规则设定** | 店长设定**卡档位与折扣率**、积分规则（怎么得 / 怎么用） | 改基础数据 |
| B11 | **员工与账号管理** | 店长维护员工账号与岗位 | 改基础数据 |

### 1.4 查询线

| # | 业务 | 一串动作（谁做什么） | 类型 |
|---|---|---|---|
| B12 | **商品与库存查询** | 库管 / 店长查库存；收银员结算前看可售量 | 只查询 |
| B13 | **库存变动查询** | 库管 / 店长查某个商品的**变动历史**，看清它的**来龙去脉**（这批货从哪来、又去哪了）：每一笔记下 **变动原因 + 数量 + 时刻 + 操作人**，并能**指回引起它的那张单据** | 只查询 |
| B14 | **单据与自助查询** | 收银员查自己经手的单；顾客查自己的预订、**销售单**、积分 | 只查询 |

### 1.5 盈亏线（店长负责）

| # | 业务 | 一串动作（谁做什么） | 类型 |
|---|---|---|---|
| B15 | **资金收付登记** | 各业务（B2 采购付款 · B5 / B7 销售收款 · B8 退货退款 · B9 办卡费）发生收付时**自动留下一笔金额记录**；**店长另外登记**不属于这些业务的收付 —— 只有**注资 / 提现**两种（**店长的资金动作就是"投钱 / 取钱"，不记日常费用**） | 动数据 |
| B16 | **盈亏查询** | 店长查看收入、支出与盈亏（**经营盈亏** 与 **现金余额** 两个指标） | 只查询 |

### 1.6 单据：三种，各自挂在哪条业务

官方要求的核心对象里有「**订单**」与「**订单明细**」——
在本设计里它就是**卖货开出的那张单据**，我们统一叫「**销售单**」，
并**没有为它单列一条业务**，理由见下表：

| 单据 | 由谁产生 | 是不是独立业务 |
|---|---|---|
| **采购申请单**（买货） | B2 商品采购：库管提交申请 → 店长审批 → 收货入库 → 付款 | **是** —— 它有"申请 → 审批"这条完整的链，本身就是业务 |
| **销售单**（卖货） | B5 门店销售 · B7 到店取货，**结算时顺带产生** | **否** —— 钱货两清即完成，没有独立的"开单"动作 |
| **预订单**（线上预订） | B6 线上预订与取消 | **是** —— 预订本身就是一条业务 |

> **为什么"订单"不是一条独立业务**：判据是「**业务 = 有明确角色执行的一条动作链**」。
> 销售单是"结算"这个动作**顺带留下的记录**，没有谁专门"去做一张订单"；
> 它的**查询**也已归 B14 单据与自助查询。
>
> **订单明细** = 销售单的**行**（一张单可含多个商品与多个数量）。
>
> 这个不对称（买货有单独立业务、卖货没有）**来自业务本身**：
> 买货要先申请、要人批；卖货是顾客当场买走、或到店取走，**钱货两清即结束**，没有需要审批的环节。

## 2 主线：从顾客到完成交易

```text
B1 商品建档、定价与上下架    库管建档 + 上报报价  →  店长定价并上架
        ↓
B2 商品采购                  库管申请 → 店长审批 → 收货入库 → 付款
        ↓
B5 门店销售  /  B6 线上预订与取消
   ├─ 门店：顾客选货 → 收银员结算收款
   └─ 线上：顾客下单 → 锁定商品 → B7 到店取货 结算交付
        ↓
B13 库存变动查询（看清货的来龙去脉）· B15 资金收付登记 · B16 盈亏查询
```

每个环节的两个要素 —— **谁做的**、**动了什么** —— 都在 §1 的表格里逐条写明。

> **不在这条主线上的**：B8 商品退货、B3 商品报损 —— 它们各有独立入口，
> 不属于「顾客到完成交易」。
> 另外，**「到期过期」不是一个业务**：它由系统自动触发、没有执行角色（见 R-13）。

## 3 业务规定（R-1 ~ R-30）

> **R-4 / R-6 / R-30 已取消**（都属原「库存盘点」业务）—— **编号留空、不重排**。

| # | 规定 | 挂在哪条业务 |
|---|---|---|
| R-1 | **「能不能卖」= 两个量**：**上架**（布尔，**只由店长决定，完全不做自动化**）+ **可售量**（数量，由业务派生）。能不能卖 = 上架 **且** 可售量 > 0。<br>**不设商品状态机**：「待定价 / 下架 / 停售」全部塌缩为"未上架"；**「缺货」也不用任何标记或状态** —— 它就是 `可售量 = 0` 这个**条件**，现算即可。因此**卖光不改上架标记**，补货一到**自动恢复可卖**，不必再走一遍店长 | B1 |
| R-2 | **展示口径（两个视角，都由条件现算、不落字段）**：<br>① **内部**（库管 / 店长 / 收银员）列表页并列展示 **可售量 · 已订量 · 在架总量 · 上架与否** 四项，**不给补货建议**；<br>② **顾客侧**：`可售量 = 0` 时显示「**暂时无货**」，购买与预订都被拒。<br>注：「暂时无货」有两种成因 —— **卖光**（在架总量 = 0）与**全被订走**（在架总量 > 0、已订量 > 0）；区别靠内部列表页那四列看出来 | B12 · B5 · B6 |
| R-3 | 报损**必须填文字原因** | B3 |
| R-5 | **「订走未取」三禁**：不能卖 / 不能再订 / 不能报损 | B5 · B6 · B3 |
| R-7 | **采购申请单状态机**：草稿 → 已提交 → **已审批** → 已收货（另有"已取消"）；**未审批不得收货** | B2 |
| R-8 | **一张采购单只对应一个供应商**（报价可以多家） | B2 |
| R-9 | **计价规则：先打折、后扣积分** ——<br>① **小计** `S` = Σ(售价 × 数量)（**折扣前**）<br>② **折扣后金额** `B` = `S × 卡折扣`<br>③ **积分抵扣** `D` = min(使用积分 ÷ 100, `S` 的 **20%**)　← 100 积分 = 1 元，单笔最多抵小计的 20%<br>④ **实付** = `B − D`<br>⑤ **获得积分** = `实付 × 1`（**1 元 = 1 分**）<br>**非会员**（无卡）：无折扣、无积分 | B5 门店销售 · B7 到店取货 |
| R-10 | **成交快照**：**销售单**的行存成交价 / 折扣 / 金额；单头存**会员卡档位** | B5 · B7 |
| R-11 | **退货按销售单的行**（支持部分退货） | B8 |
| R-12 | **销售单状态机**：已付 / 部分退款 / 已全退 | B5 · B7 · B8 |
| R-13 | **预订有效期 + 到期自动过期**：**由系统自动触发，没有执行角色**（技术实现留到后面） | B6 线上预订与取消（产出的规则） |
| R-14 | **预订单状态机**：有效 / 已取 / 已过期 / 已取消 | B6 · B7 |
| R-15 | 预订**不冻结**金额 / 折扣 / 积分；自提时按**当时**的售价与**卡档位**重算 | B6 · B7 |
| R-16 | 过期 / 取消**不产生资金流水** | B6 · B15 |
| R-17 | **盈亏拆两个指标**：<br>① **经营盈亏** = 只算各业务**自动产生**的收付（B2 采购付款 · B5 / B7 销售收款 · B8 退款 · B9 办卡费）；<br>② **现金余额**（= 店内资金总额）= 全部收付，**含店长的注资 / 提现** | B16 |
| R-18 | 收付实现制；库存积压不进盈亏；不做会计口径毛利 | B16（另见 `docs/spec-scenario.md` §5 边界声明） |
| R-19 | **会员卡分档与权益**：卡**只有两档** —— **银卡折扣 0.95 · 金卡折扣 0.9**；会员身份在结算时生效（享折扣、可积分）。<br>**没有"普通会员"这一档** —— 不买卡就是**非会员**（无折扣、无积分）。**办卡费的具体金额待定** | B9 会员办理 · B10 会员规则设定 |
| R-20 | **不做升级 / 降级** —— 会员的档位**不会自动变化**，只由"买哪张卡"决定。<br>（原「等级只升不降」**作废**：那是"按累计消费升级"时代的说法，买卡制下不适用） | B9 会员办理 · B10 会员规则设定 |
| R-21 | **入会 = 购买会员卡；卡一年有效**，到期后不再享有会员权益（因此 B9 办卡**收费**，盈亏线上有一笔"办卡费"收入） | B9 会员办理 |
| R-22 | **每张单据都有一个单号** —— 它是这张单**对外的标识**。**卖货与预订的单据会交给顾客一份**，顾客凭单号就能找回原单（向供应商买货的那张不进顾客手里）。**预订单对外的那个编号就是它已有的「预定码」**，不另起一个 | B2 · B5 · B6 · B7 |
| R-23 | **退货凭单号即认单** —— 不需要会员身份，也不要其它证件：**非会员凭单号同样能退**。会员也可以凭手机号找回自己的单，两者取其一即可 | B8 |
| R-24 | **所有库存变化都必须留下变动记录**；**在架总量的变动原因只有四类：购入 · 卖出（含到店取货）· 退货 · 损坏（报损）**；**预订 / 取消 / 过期不记在架变动**（货没离店，只动「已订量」）；**在架总量必须等于变动记录的累加，任何人不得手动改库存**。<br>**每笔变动还要能指回引起它的那张单据**（采购 / 销售 / 预订单 / 退货 / 报损）—— 只记"某时刻卖出 3 本"指不到是哪一笔，就谈不上"来龙去脉" | 所有改变库存的业务（B2 · B3 · B5 · B6 · B7 · B8） |
| R-25 | **操作人留痕** —— 口径（记什么 / 不记什么 / 系统自动动作怎么记）见 `docs/spec-roles.md` **§4 第 4 条**，此处**不复述** | 除"只查询"类以外的**全部业务**；**留痕对象见 §4** |
| R-26 | **已订量 = 全部「有效」预订单的行数量之和** —— 商品侧的计数必须与单据侧的记录对得上 | B6 · B7 · B12 |
| R-27 | **换卡规则**：银卡持卡人 → ① **按差价**买金卡：**有效期不变**；② **全价**买金卡：**有效期更新**。<br>**到期后重买**（同档或高档）一律是全价 → **有效期更新**。卡**只能往高买**，不设降档 | B9 会员办理 · B10 会员规则设定 |
| R-28 | **积分留痕与余额**：每次积分变动都留下记录（怎么得的 / 怎么用的 / 退货收回的）；**积分余额 = 全部积分变动之和** —— 与 R-24 同构，**任何人不得手动改积分**。<br>**退货回滚**：退货时把该次消费**获得的积分收回**；**若这些积分已被花掉，余额允许为负** —— 否则会出现"花光积分再退货"的漏洞。<br>**退款只退实付**（`B − D`）—— 原单**用掉的积分 `D` 不退**。<br>**部分退货**只处理**退回行**对应的那部分（实付与积分均按行小计占比折算） | B5 门店销售 · B7 到店取货 · B8 商品退货 · B9 会员办理 |
| R-29 | **收货按实收数量入库** —— **不处理"实收 ≠ 申请"的差异**：申请只是意图，入库才是事实 | B2 商品采购 |

> **退货时"原单用掉的积分"不退** —— 顾客当初用积分抵掉的那部分钱（R-9 的 `D`）
> **不返还**，退款**只退实付**（`B − D`）；同时该次消费**获得的积分**按 R-28 收回。
> 一句话：**退的是"现金实付"那部分；积分抵扣是已经用掉的优惠，不找回来。**

## 4 留痕对象清单（R-25 附表）

| 留痕对象 | 为什么值得记 |
|---|---|
| 采购申请的**审批人** | 花钱的决策要有人负责（**审批与付款是同一步、同由店长完成**，故不单列"付款人"） |
| 销售的**收银员** | 收错钱能追 |
| 退货的**受理人 + 退款** | 钱往外走，最需要追 |
| 预订的**取货核销人** | 取货码被冒领 / 重复核销能追 |
| 报损的**登记人** | 货没了总得有人说明 |
| 资金的**登记人** | 注资 / 提现 |
| **定价人** · **会员规则设定人** · **账号维护人** | 改价格、改规矩、发账号都要有出处 |

> **不记**：采购单的**收货人** —— 收货动作本身有入库记录，申请与报价又都是库管提的，
> 重复记一层没有增量信息。
