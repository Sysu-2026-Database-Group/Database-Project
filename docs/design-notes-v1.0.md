### 1.2 判定规则（表 → 五种角色）

**四问**（依次问，**第一个成立**的即为它的角色）：

| ① 有**自有标识**（不依赖别的表就能指认一行）？ | ② 是"一对多"里**多**侧的行、要靠单头才指认得出？ | ③ 是 **`M:N` 本身**（两端各一列做复合主键、还带自己的属性）？ | ④ 是"**单件记录一次**"的事实、**只增不改**、没有状态机？ | ⑤ 是超类的**可选补充信息**（只对一类实例有意义、与同类互斥）？ |
|---|---|---|---|---|
| **实体** | **弱实体（明细）** | **联系实体** | **事件（流水）** | **子类型（细节）** |

**读法**：从①向下取**第一个**成立的判定；**子类型是"角色叠加"** —— `book` / `toy` **有自有标识**（`isbn` / `inner_code`），所以它们是**实体**，同时**扮演 `goods` 的可选子类型**，故 §0 总览的角色列写作"**实体（子类型 / 细节）**"；总览"只允许五种"指的是**主角色**。

**为什么单据头是实体、三张流水是事件**（同一个"业务发生了"的两类形态）：单据**有状态与生命周期**（提交 / 审批 / 完成 / 取消），能被别的表反复引用（付款、入库、回滚都挂它）→ **实体**；流水是"**事后不可回改的事实**"（只增不改、无状态机）→ **事件**。

### 1.3 三条画图规则（阶段 3 试画时按它执行；符号见 `er-mapping` 附录 A）

1. **汇总边**：`C-2`（17 类留痕列）与 `C-8`（3 张明细表的 `goods_id`）在库里是**多条同类外码**，图上**汇总表达并注明包含哪些列** —— `C-2` **画一条虚线**到 `employee`；`C-8` **不另画线**（三张明细已各自与单头相连，见 `C-16` / `C-19` / `C-26`），**只用备注框注明**；否则 19 张表之间会出现二十余条同形线；
2. **子类型**：`goods` → `book` / `toy` 用**子类型**表达 —— **已定：两条可选边 + 空心三角**（不用单条 ISA 线）；**互斥由 `CK_goods_category` 保证**，图上不画约束；
3. **只画直接联系**（附录 A 约定 4）—— 隔着中间表的两表之间不连线。

### 2.3 哪些联系需要通过中间实体表示

- **`supplier` ↔ `goods`（`M:N`）→ `supplier_quote`**（`C-10` / `C-11`）—— 官方提示 1 所说的"关联表"正落在这一张；
- **`sale` ↔ `goods`（`M:N`）→ `sale_item`**（`C-19` 管"属于哪张单"、`C-8` 管"哪件商品"）；`reservation` / `purchase_request` ↔ `goods` 同形；
- **`goods_return` ↔ `sale_item`**：退货"退哪几行"用**明细对明细**（`C-25`）表达，而不是"单对单" —— 这样**部分退货**才有落点；
- **"同一商品在一张单里可否重复出现"**：v0.1 **明确取"不重复"** —— 4 张明细表都用 `(单, 商品)` 唯一约束（退货明细是 `(退货单, 原销售明细)`），多件**用数量列**表达。这是官方提示 1 给出的两种处理方式之一，**已明确选择并落实为约束**（不是默认假设）；
- **`M:N` 已全部落表**：全库没有"两端都是 N 却不落表"的联系（附录 A 约定 4 因此说"菱形用得少"）。

### 2.4 与字典、官方示例需要说明的对照

- **"库存"没有独立实体**：① `goods` 上的两个**账面计数**（`stock_total` / `reserved_qty`）② 真源是 **`stock_movement`** ③ **可售量**派生、不落库（边界清单 §3 判据 1 / 2）；
- **"会员卡"没有独立实体**：档位配置（`card_type`）+ 会员档案（`member`）两张实体；卡的**有效期是 `member` 的属性**，卡本身不单独建表；
- **`goods` 的标识只有代理键**：图上标识写 `id`；`book.isbn` / `toy.inner_code` 是**子类细节的标识**，不是商品标识（字典 §1.1）；
- **命名例外两处**：`card_type.set_by` / `set_at`（全库唯一不用 `_by` / `_at` 的留痕列）；`employee.phone` / `member.phone` **直接用业务键做主标识**（不是代理键）；
- **同一含义两处出现（全部有意）** —— 分两类：

| 一处 | 另一处 | 为什么两处都要 |
|---|---|---|
| `goods.stock_total` · `goods.reserved_qty` | `Σ stock_movement.quantity` · `Σ 有效预订单行` | 账面计数省去每次重算，但**必须对得上**（R-21 / R-23 → **I-04**） |
| `member.points_balance` | `Σ point_movement.points` | 同上（R-25 → **I-10**） |
| `member.card_level` · `card_type.card_fee` / `.discount_rate` | `sale.card_level` / `sale.discount_rate` / `fund_flow.amount` | **当前参数** vs **成交时点快照**（R-8 / R-24）—— 快照不可回改，也**无法事后校验**（→ **I-20** 一族） |

- **预订单不挂会员**：`reservation.phone` 是**下单手机号** —— A10 明文"**订的人不一定是会员**"，所以它**没有外码**；图上 `reservation` 与 `member` 之间**没有连线**，这是**有意不建联系**（不是漏画）。
- **官方示例的对应**：**"订单"** = `sale`（+ `sale_item`）；**"会员 / 散客"** = `sale.member_phone` **可空**（`C-13`）；**"库存查询"** = `goods` 的两个计数 + `stock_movement` 明细（阶段 4 的 §3.1–§3.3 展开）。

- **图上怎么表达**：`sale`（实体 · 单据头）——**`C-19`**→ `sale_item`（**弱实体**，明细侧 `(1,1)`）——**`C-8`**（汇总边）→ `goods`（`(0,N)`—`(1,1)`）。

  **退货挂"原销售明细"**：`C-25`（`sale_item` → `goods_return_item`，明细对明细），所以"只退某一行"才有落点。
- **库里对应**：
  - 表 / 列：`sale`(`no` · `subtotal_amount` · `discount_rate` · `point_deduction_amount` · `paid_amount` · `status`) · `sale_item`(`sale_id` · `goods_id` · `quantity` · `unit_price`) · `goods_return_item`(`return_id` · `sale_item_id` · `quantity` · `refund_amount`)
  - 约束：`UQ_sale_no` · `FK_sale_item_sale_id` · **`UQ_sale_item_sale_id_goods_id`**（**同一张单里同一商品只一行**，多件用 `quantity`）· `CK_sale_amount`（折扣与实付的等式、抵扣 ≤ 20%）
  - 校验：**`51212`**（单头金额 = Σ 行金额）· `51213`（退货金额 / 原单归属 / 累计退货量）
- **最小实例**（样例 **S2 = `S20260914-01`**，一单两行、两种类别）：

```text
sale 2 (S20260914-01)  小计 97.00 · 折扣 0.95 · 积分抵扣 1.00 · 实付 91.15 · 状态「部分退款」
  sale_item 2：活着 ×2   @39.00  = 78.00      ← 图书
  sale_item 3：拾光帆布袋 ×1 @19.00 = 19.00   ← 文创
复算：2×39.00 + 1×19.00 = 97.00 → ×0.95 = 92.15 → −1.00（积分抵扣）= 91.15 ✓ 与样例一致
部分退货 R1 只退「帆布袋」那一行 → 退货明细指向 sale_item 3；另一行不受影响 ✓
```

- **结论**：一单多行、跨类别商品、部分退货在**图上与库里都有落点**；"至少一条明细"是**业务要求**，库里靠**事务级写入**保证（外码管不了，→ **I-11**）。
  样例**未覆盖**：**同一商品在同一张单里出现两次 —— 这不是"未覆盖"，而是被 `UQ_sale_item_sale_id_goods_id` 明令禁止**（多件用数量列表达，官方提示 1 的两种处理之一，v0.1 已明确选择）。

### 3.2 会员 / 散客购买

- **图上怎么表达**：`member` ↔ `sale`（**`C-13`**，`sale` 侧 **`(0,1)`** —— **散客为空**）· `member.card_level` → `card_type`（`C-3`，`(1,1)`）· 折扣率 / 办卡费是**时点取值**（无外码、图上不画线）· 积分三条边（`C-14` / `C-23` / `C-29`）。
- **库里对应**：`sale.member_phone`（**可空外码**）· `sale.card_level` / `sale.discount_rate`（**成交时点快照，无外码**）· `point_movement`(`change_type` · `points` · `sale_id` · `return_id`) · `member.points_balance` · `fund_flow`(`reason_type` · `member_phone`)
  校验：**`51211`**（余额 = 积分流水之和）· **`51215`**（回滚挂原单与会员）· **`51217`**（销售收款恰好 1 笔 = `paid_amount`）
- **最小实例**：

```text
会员（13900000001）：S1 / S2 的成交快照 = 银卡 0.95；09-19 按差价换金卡（+30.00，fund_flow 第 12 笔）
  → member 现在是金卡，而旧单仍是银卡折扣 —— 「当前值 vs 快照」两处并存、互不改写 ✓
散客（S3 = S20260913-01）：member_phone 为空 · card_level 为空 · 折扣 1.00 · 不产生任何积分
  同时挂 reservation 1（C-24，取货销售）—— 且该预订的下单手机号 13700000009 不是会员（A10「订的人不一定是会员」）
积分链：+111（S1 获得）· −100（S2 抵扣 1.00 × 100）· +91（S2 获得）· −17（R1 回滚 ⌊91×19/97⌋）· −111（R2 回滚）
  → 111 − 100 + 91 − 17 − 111 = −26 = member.points_balance ✓（余额为负是 R-25 允许的）
```

- **结论**：**"会员可选"在图上标 `(0,1)`、库里由"可空外码"实现** —— 两边一致；**不得因为"样例里只有 2/3 张单是会员单"去反推基数**（官方提示 3），基数依据是 **B4/B6 的会员可选**。
  样例**未覆盖**：① **纯门店散客单**（无预订、非会员）；② **会员取货单**（`member_phone` 与 `reservation_id` 同时非空）；③ **零退款 / 零回滚**（R-25 规定"零额不生成流水"，两笔退货都有退款额）。

### 3.3 库存查询

- **图上怎么表达**：`goods` 上的两个**账面计数**（`stock_total` / `reserved_qty`）+ **派生属性「可售量」**（虚线椭圆，**相减现算、不落库**）；真源是 `stock_movement`（事件流水，`C-9`）与 `reservation_item`（有效预订行，`C-26`）。
- **库里对应**：
  - 列：`goods.stock_total` · `goods.reserved_qty` · `goods.on_shelf` · `goods.price` · `stock_movement.quantity` · `reservation_item.quantity`（配 `reservation.status = '有效'`）
  - 校验：**`51210`**（在架 = 流水之和 · 已订量 = 有效预订行之和，两个等式一起验）
  - 查询：**`db/query.sql` Q3**（现算 `available_qty` 与 `saleability`）· **Q2**（含"有货未售"的左连接演示）
- **最小实例**（Q3 输出，业务时点 as-of `2026-09-20 12:00`）：

| 商品 | `stock_total` | `reserved_qty` | 可售量 | 为什么是 0 / 不是 0 |
|---|---|---|---|---|
| 活着 | 6 | 6 | **0** | **全被订走**：`reservation 2`（状态**有效**）订了 6 本 → 按 R-2 不可售 |
| 百年孤独 | 0 | 0 | **0** | **卖光**：进货 3、取货卖出 3（S3） |
| 拾光帆布袋 | 10 | 0 | 10 | 正常可售 |
| 拾光书签 | 19 | 0 | 19 | 进货 20、**报损 1**（报损**无单据**，走 `C-9` 的报损分支） |

```text
复算（在架 = 变动累加）：活着 = +5(req1) +3(req2) −3(S1) −2(S2) +3(R2) = 6 ✓
复算（已订 = 有效预订行）：活着 = reservation 2「有效」×6 = 6 ✓
Q3 同时列出「按明细重算的已订量」与「账面 reserved_qty」两列，两者相等 —— 这就是 51210 的人工可见版
```

- **结论**：**"可售量 = 在架 − 已订"是现算条件、不落库**（边界清单**不进库 #1**），图上用**虚线椭圆**表达 ✓；"能不能卖"还要 `on_shelf = 1 且 price 非空`（R-2）。
  样例**未覆盖**：① **未上架商品**（`on_shelf = 0`，样例 4 件都已上架）；② **预订到期的释放时点**（Q3 用 as-of 时点近似，`reservation 2` 在 09-21 之后才会过期）。

> **纪律**：实例只用于**验证与演示**；**结论一律以业务规则为准，不得据实例反推基数**（官方提示 3）。
> 样例**未覆盖**的情形要**明写"未覆盖"**，不得写成"不可能"。

## 5 被否掉的方案与理由（阶段 2 完成 · 2026-10-11）

> **来历的另一半**：`task-week-5.md` §3 条 14 要求"能解释每条联系与基数的来历（含**被否掉的方案**）"。下表每一条都能在仓库里找到出处：`docs/er-mapping-v1.0.md` 的对应节、`docs/issues-v0.1.md` 的"刻意不开 / 保留"理由，或第 2 周的设计记录（`drafts/plan-week-2.md`）。

| # | 曾考虑的方案 | 为什么不采用 |
|---|---|---|
| 1 | 把 `book` / `toy` **合进 `goods`**（一张宽表） | 两类商品属性差别大（作者 / 出版社 / 页数 **vs** 规格），合表会造出大量空值；改为**分开存 + `CK_goods_category` 保证互斥**（`D-8` 两类商品分开存） |
| 2 | **反转外键方向**，让"细节行必须被某件商品引用" | 代价大于收益（要改插入顺序与键结构）；改由"细节行**随商品建档产生**"的业务约定承担（**I-05** 保留） |
| 3 | 在 `goods_return` 上存 `rolled_back_points`（回滚积分数） | 回滚是**积分流水的一类变动**，可由 `point_movement` 算出；再存一份必然多一处不一致（第 2 周已删该列） |
| 4 | 流水用"**来源类别 + 单号**"做弱引用（一列塞单号） | 那样**建不了外码**；改为**多个可空外码**（类别与外键一一对应），互斥由 `CK_stock_movement_source` / `CK_fund_flow_source` 保证 |
| 5 | 给 `fund_flow` 加 `reservation_id`（预订也走收款） | 预订**不收款、不锁价**（R-13 / R-14）→ 资金行不需要预订外码（第 2 周讨论记录） |
| 6 | 给"可空列要唯一"直接加**普通 `UNIQUE`**（`goods.toy_code` / `book_isbn` / `sale.reservation_id`） | SQL Server 把**多个 `NULL` 视为重复** → 第二行就插不进去；正解是**筛选唯一索引**（**I-07** / **I-16**） |
| 7 | 单头金额改成**视图现算**（去掉快照列） | R-8 要求**成交时点快照**；现算会丢掉时点稳定性（**I-14** 的改进方向已注明"不建议"） |
| 8 | 给库存计数 / 积分余额加 `>= 0` 约束 | R-25 明说**退货可能使余额为负**；计数由"等于流水之和"保证（`er-mapping` §8.5 的"刻意不开"） |
| 9 | 去掉 `UQ_supplier_name`（不把名称当身份） | 去掉唯一反而让"**选错供应商**"变成可能（**I-08** 保留） |
| 10 | 用**外码**表达"**至少一条明细**" | 外码只保证"引用的对象存在"，管不了"至少一条"（官方提示 2 同指此点；**I-11** 保留 + 事务级写入保证） |
| 11 | **单件追踪**（每册书 / 每件文创单独编号 + 单件流水） | 场景规则 4 明确"库存**仅以数量记录**"（边界清单**不进库 #18**） |
| 12 | 给商品 / 会员做**状态机**（"待定价 / 下架 / 缺货"、"会员有效 / 失效"列） | R-1 明文"**完全不做自动化**"：状态塌缩为"未上架"，有效期**现算**（`er-mapping` §3.2 / §8.2） |
