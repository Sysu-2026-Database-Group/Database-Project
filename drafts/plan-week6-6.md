## 3. 函数依赖、更新异常与规范化分析

### 3.1 逐表分析范围

对现有 19 张表逐表建立分析记录，再分析分解后的目标关系；下列分组只用于安排工作，不意味着同组表必须合并或拆分。

正式分析归口 [依赖与规范化设计说明](../docs/design/design-normalization-v1.0.md)。当前 19 张表均已有初稿（19 / 19，待统一核对），不能视为目标方案或迁移实现已完成。

| 分组 | 对象 | 重点 |
|---|---|---|
| 主体与会员卡参数 | `employee`、`card_type` | 业务码与候选码、岗位及档位取值；参数当前值与历史成交快照的区别 |
| 商品与供应 | `goods`、`book`、`toy`、`supplier`、`supplier_quote` | 商品标识、细节一对一取舍、名称的唯一性、复合码与报价属性的依赖 |
| 会员与积分 | `member`、`point_movement` | 当前档位、到期日、积分流水及余额冗余；余额一致性与范式分别分析 |
| 采购 | `purchase_request`、`purchase_request_item` | 单号与代理键、“父单 + 商品”候选码、批次进价与数量；状态规则与函数依赖分别记录 |
| 销售与预订 | `sale`、`sale_item`、`reservation`、`reservation_item` | 成交单价、折扣及金额快照；预订不冻结价格，整单取货与标识映射 |
| 退货与账目 | `goods_return`、`goods_return_item`、`stock_movement`、`fund_flow` | 原销售行决定商品、退款分摊、流水来源；数量 / 金额汇总、资金链与冗余维护 |

### 3.2 每张表的分析模板

每张表填写：关系模式与业务含义；主码及全部候选码；关键函数依赖及业务依据；插入、修改、删除异常及示例；1NF、2NF、3NF 判断；保留 / 拆分 / 合并结论及理由；目标属性与码；相关问题编号、迁移步骤和验证用例。

- **1NF**：检查字段是否保存多个值，区分说明性文本与需要独立查询的业务属性。
- **2NF**：考虑全部候选码及其真子集；代理键为单属性不代表其他复合候选码没有部分依赖。
- **3NF**：对每个非平凡依赖 `X → A`，核对 X 是否为超码，或 A 是否为主属性；不要只检查所选主键。
- **时点语义**：商品编号决定当前商品资料，不直接决定历史销售成交价；当前档位参数不直接决定历史销售折扣或旧办卡收费。金额快照不能因看似重复就删除。
- **冗余取舍**：库存计数、积分余额、单头汇总与资金余额分别说明保留目的、更新路径和维护成本；跨行聚合一致性不是函数依赖分析的替代品。
- **分解论证**：根据函数依赖说明无损连接与依赖保持；样例连接结果用于发现错误，不能代替一般性论证。若依赖不能直接保持，说明额外检查方式与成本。

已有结构合理时保留，并给出分析证据。若需要演示更新异常而实际核心表已满足范式，可使用独立演示关系，不破坏项目原数据。

业务规则以 `docs/specs/spec-businesses.md` 的 R-1—R-26 为准。每个新增场景至少有一组可指认的数据、明确的时间和预期结果；可共享新建基础对象，但不同测试之间不得留下未经说明的状态影响。

| 编号 | 新增场景 | 数据与操作安排 | 主要验收点 |
|---|---|---|---|
| W6-S01 | 商品展示与定价 | 新建未定价且未上架商品、已定价但未上架商品，以及已上架可售商品 | 顾客查询仅展示已上架商品；未定价商品不能直接上架成交。对应 R-1、R-2 |
| W6-S02 | 库存部分占用 | 为新商品采购入库，再建立有效预订，使在架量大于已订量且已订量大于 0，例如在架 10、已订 3、可售 7 | 三个量能够对账；仅可销售剩余可售量，不能侵占已订量。对应 R-4、R-23 |
| W6-S03 | 采购各阶段 | 分别保留草稿、已提交、已审批待收货、已取消的新采购单；保留旧已收货单，并新增一次完整采购 | 留痕与状态一致；至少一张新采购单包含多个商品。取消态不产生采购付款或入库。对应 R-5、R-6、R-26 |
| W6-S04 | 当前银卡与金卡成交 | 新建有效银卡会员及有效金卡会员，各完成新销售；另安排正积分会员的合法积分抵扣 | 档位折扣、抵扣上限、实付和获赠积分计算正确，积分余额有流水支撑。对应 R-7、R-17、R-25 |
| W6-S05 | 会员到期与重买 | 为新会员设计到期当天、次日失效、过期后全价重买及有效期内重买的独立用例；正负积分分别检查 | 到期当天仍有效；失效时无折扣、无获赠或抵扣，原积分保留；重买按规则恢复权益。到期与闰日用固定测试日期验证。对应 R-18、R-24 |
| W6-S06 | 预订取消与过期 | 新增已取消、已过期的预订历史，以及用于执行取消、到期操作的独立有效预订 | 释放全部已订量，不改在架量，不产生资金和积分流水；自动过期不虚构员工。静态终态记录与自动处理测试分别验证。对应 R-11、R-12、R-14、R-23 |
| W6-S07 | 多商品预订与会员取货 | 新建含至少两种商品的预订，由新会员整单取货并生成销售单 | 所有明细一次核销；销售单同时关联会员和预订单；在架与已订同步扣减，收款、出库及积分记录一致。对应 R-12、R-13、R-21、R-23 |
| W6-S08 | 预订后调价与历史快照 | 用新商品在预订后、取货前调价，再取货成交；成交后再次调价。卡档位参数修改另设事务用例并回滚 | 取货按成交时价格与权益计算；后续调价或参数变化不回改已成交的明细和单头。对应 R-8、R-13、R-17 |
| W6-S09 | 散客销售与多行退货 | 新建不关联会员的门店销售，至少包含两种商品，再凭单号办理多行退货 | 单号可定位原单；退款按原实付分摊、库存回收入库；散客交易不产生积分流水。对应 R-9、R-20、R-25 |

### 6.4 补充边界与失败用例

以下用例在独立事务或可重置的测试副本中执行，不把非法数据留在扩充后的基线中。每项记录初始状态、操作、预期、实际结果，以及失败后的库存、积分、资金和相关记录数。

| 类别 | 必测用例 | 预期 |
|---|---|---|
| 码与引用完整性 | 重复主码、重复单号、重复“父单 + 商品”、不存在的外码 | 拒绝写入，原有合法数据不变 |
| 数量与库存 | 数量为 0 或负数、超过可售量、侵占已订量、报损未填原因 | 拒绝操作，不留下部分单据或流水 |
| 采购状态 | 未审批付款或收货、审批后取消、终态回退、收货数量与申请不一致 | 按既定业务规则拒绝，原状态与账目不变 |
| 预订状态 | 部分取货、过期或取消后取货、不同请求重复操作终态 | 拒绝操作，不重复扣减库存或收款 |
| 积分与退货 | 超积分余额或抵扣上限、跨原单退货、累计超数量退货 | 拒绝操作；合法多次退货的累计金额与积分无尾差 |
| 重复请求 | 同一次收货、取货、退款、取消请求重复提交 | 返回原结果，不重复产生业务记录、资金、库存或积分变化 |
| 角色权限 | 收银员改卡参数、库管执行收款或退款、无权限角色查询资金 | 越权失败，授权角色的合法操作成功 |
| 事务完整性 | 在单据、库存、积分或资金写入中途制造失败 | 整笔回滚，不出现只有单据或只有流水的状态 |

测试前逐项确认当前实现能力。已有约束直接复用；尚未实现的状态控制、重复请求识别或自动处理，明确记录为“待实现”或“待验证”，并安排第六周改进或后续应用阶段落实，不能把插入终态样例当成业务功能已经通过。

### 6.5 实施顺序与交付物

1. **确认场景与数据清单**：逐项登记 W6-S01—W6-S11 的新增对象、主码 / 单号、时间、规则依据和预期值；确定扩充后的业务截面、逐表计划数量及成员责任。
2. **保存旧基线**：在 v0.1 副本上导出逐表数量与关键结果，核对旧场景和原三条账；备份后再开展结构修改。
3. **完成依赖分析和迁移设计**：先明确目标关系模式、旧新标识映射、无损连接与依赖保持依据，再编写并执行 `migration.sql`。样例扩充与结构迁移分别说明，避免混淆行数变化的原因。
4. **先验证迁移保留性**：在仅迁移、尚未扩充的副本上运行旧场景的等价查询，确认订单、明细、金额、库存、积分和资金语义保持。

6. **编写场景回归**：将旧场景、新场景和边界用例纳入 `db/regression.sql`，分别记录旧截面预期、新截面预期和失败操作预期；权限及自动处理测试写明执行入口和所需身份。
7. **完成对账和文档同步**：规划在实施时同步数据字典、ER 图、数据库执行说明与 AI 使用记录；实际运行输出保存到 `db/results/`，报告中说明新增场景、迁移前后结果及未实现项。

以上路径为后续实施时的拟定产出。样例扩充按第 5 节的阶段安排执行；此处保留早期实施顺序；脚本和装载现已完成，当前状态见正式验收记录。

### 6.6 验收标准

- **旧场景保留**：77 行原始样例在迁移后的结构中可追溯；拆表后允许物理行数变化，但旧业务字段、关系及关键查询结果可还原，不以“总数相同”代替逐项验证。
- **新场景覆盖**：W6-S01—W6-S11 各有样例或可执行用例及对应结果；未完成的操作测试明确列出原因与后续安排，不记为通过。
- **数量可核对**：提交扩充前后逐表数量，区分原始记录、迁移生成记录、新增样例和测试临时记录；每条新记录有场景用途，临时测试回滚后不计入基线。
- **四类数据一致**：在架量等于库存流水累加，已订量等于有效预订明细汇总，积分余额等于积分流水累加，资金流水前后余额连续；采购付款、销售收款和退款均能追溯来源。
- **统计有明确口径**：旧截面仍能复核现金 1430.30、经营盈亏 −69.70；扩充后的新截面单独计算并记录预期，按商品、日期和会员的统计能够与明细对账。
- **失败不会污染数据**：非法输入、越权、重复请求和中途失败均有实际结果与前后状态证据；暂未实现的规则如实标记。
- **脚本可复现**：从指定的 v0.1 副本按“旧基线 → 迁移 → 旧场景回归 → 扩充 → 完整回归”执行，结果符合预期，并写清失败恢复和再次运行条件。
