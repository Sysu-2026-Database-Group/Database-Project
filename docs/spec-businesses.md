# 拾光书店 · 业务清单与业务规定

**性质**：正式文档（已敲定）。
**范围**：定义业务内容与业务规定；字段、类型与 SQL 见数据字典和建库脚本。

---

## 0 阅读约定与术语

**阅读约定**

- 提到业务一律「**编号 + 名称**」并写（例：「B5 线上预订与取消」），不裸用编号。
- **业务 = 有明确角色执行的一条动作链**；其余一切（状态表达、快照、展示口径、对账等式……）
  都是**规定**，附着在已有业务上，**不因此新增业务条目**。
- 本文的**规定即为定案**，不再另设"定案记录"节。
- 本文按当前有效业务连续编号；历史草稿中的旧编号不能用于实现。

**术语**（本文与 `docs/spec-scenario.md`、`docs/spec-roles.md` 共用同一套）

| 术语 | 含义 |
|---|---|
| **在架总量** | 货架上真实有多少 —— **含已被订走、还没取走的货**；也是**与"变动累加"对账的基准** |
| **已订量** | 已被订走、等待取货的数量 |
| **可售量** | `在架总量 − 已订量` —— 还没有主、可以卖的货 |
| **上架** | 一个布尔值，表达**店长的意思**：这个商品允不允许卖 |
| **能不能卖** | `上架 且 可售量 > 0` |
| **单据** | 采购申请单、销售单、预订单和退货单；四者都按单头与明细记录 |

## 1 业务清单（15 条）

本项目不做库存盘点：只按采购、销售、退货、报损改变库存，不允许手调数量。

### 1.1 货线（库存管理员主导）

| # | 业务 | 一串动作（谁做什么） | 类型 |
|---|---|---|---|
| B1 | **商品建档、定价与上下架** | 库管登记商品（**售价留空**）并**上报各供应商的当前报价** → 商品**未上架**（顾客不可见）→ 店长参考报价**定价**并**置为上架** → 商品具备展示与销售资格；有可售量后才能成交。店长此后可调价，也可**下架** | 改基础数据 |
| B2 | **商品采购** | 库管查看多家供应商的**当前报价**并提交申请（单据记录选中供应商与该批进价）→ 店长审批 → **店长一次付款** → 库管按申请数量一次取货入库 | 动数据 |
| B3 | **商品报损** | 库管登记报损 → 库存减少 | 动数据 |

库管上报报价后，店长从未上架商品清单接续定价与上架，不另设定价申请单。供应商报价只保存当前值，供定价和采购选择参考；采购明细另存该批进价。

### 1.2 钱与顾客线（收银员主导）

| # | 业务 | 一串动作（谁做什么） | 类型 |
|---|---|---|---|
| B4 | **门店销售** | 顾客选货 → 收银员结算收款 → **生成销售单**（头 + 行）；库存减少，会员权益生效 | 动数据 |
| B5 | **线上预订与取消** | 顾客线上下单（**登记手机号**）→ 系统发**预定码**（唯一凭证）→ **增加已订量、减少可售量**（不收款、不动价）；顾客凭**手机号 + 预定码**自行取消，收银员核对后也可代取消 → 释放已订量 | 动数据 |
| B6 | **到店取货** | 顾客报**手机号 + 预定码** → 收银员核对预订并结算 → 收款 → **生成销售单**（头 + 行）→ 商品交付（库存离店） | 动数据 |
| B7 | **商品退货** | 顾客请求并**出示单号** → 收银员**凭单号**核销原单、**退款（只退实付）**、**回滚该次获得的积分** → 库管回收入库 | 动数据 |
| B8 | **会员办理** | 顾客申请 → 收银员开卡登记并**收取办卡费**（会员身份在结算时生效） | 动数据 |

### 1.3 决策线（店长主导）

| # | 业务 | 一串动作（谁做什么） | 类型 |
|---|---|---|---|
| B9 | **会员卡档位配置** | 店长维护银卡、金卡的当前办卡费和折扣率；新参数用于之后的办卡、换卡和结算，已成交单据不回改 | 改基础数据 |
| B10 | **员工与账号管理** | 店长维护员工账号与岗位 | 改基础数据 |

### 1.4 查询线

| # | 业务 | 一串动作（谁做什么） | 类型 |
|---|---|---|---|
| B11 | **商品与库存查询** | 库管、店长、收银员查内部库存；顾客查看已上架商品及是否有货（R-2） | 只查询 |
| B12 | **库存变动查询** | 库管 / 店长查某个商品的**变动历史**，看清它的**来龙去脉**（这批货从哪来、又去哪了）：每一笔记下 **变动原因 + 数量 + 时刻 + 操作人**，并能**指回引起它的那张单据** | 只查询 |
| B13 | **单据与自助查询** | 收银员查自己经手的单；顾客凭**手机号 + 预定码**查自己的预订；会员验证归属后查自己的销售单与积分。非会员销售单由收银员凭单号核对，不提供无身份的线上自查 | 只查询 |

### 1.5 盈亏线（店长负责）

| # | 业务 | 一串动作（谁做什么） | 类型 |
|---|---|---|---|
| B14 | **资金收付登记** | 各业务（B2 采购付款、B4 / B6 销售收款、B7 退货退款、B8 办卡费）发生收付时**自动留下一笔金额记录**；**店长另外登记**不属于这些业务的收付 —— 只有**注资 / 提现**两种（**店长的资金动作就是"投钱 / 取钱"，不记日常费用**） | 动数据 |
| B15 | **盈亏查询** | 店长查看收入、支出与盈亏（**经营盈亏** 与 **现金余额** 两个指标） | 只查询 |

### 1.6 单据与业务的对应

单据记录业务发生的事实，业务清单按动作流程划分。课程中的“订单”和“订单明细”在本项目分别对应销售单 `sale` 和销售明细 `sale_item`。

| 单据 | 所属业务 | 记录内容 |
|---|---|---|
| 采购申请单 | B2 商品采购 | 供应商、申请商品、批次进价及审批状态 |
| 销售单 | B4 门店销售、B6 到店取货 | 成交商品、数量、价格和结算快照 |
| 预订单 | B5 线上预订与取消 | 预订商品、数量、有效期及处理状态 |
| 退货单 | B7 商品退货 | 原销售单、本次退回的明细与退款 |

四种单据均有单头与明细，查询归 B13 单据与自助查询。

## 2 主线：从顾客到完成交易

```text
B1 商品建档、定价与上下架    库管建档 + 上报报价  →  店长定价并上架
        ↓
B2 商品采购                  库管申请 → 店长审批 → 付款 → 取货入库
        ↓
B4 门店销售  /  B5 线上预订与取消
   ├─ 门店：顾客选货 → 收银员结算收款
   └─ 线上：顾客下单 → 锁定商品 → B6 到店取货 结算交付
        ↓
B12 库存变动查询（看清货的来龙去脉）、B14 资金收付登记、B15 盈亏查询
```

每个环节的两个要素 —— **谁做的**、**动了什么** —— 都在 §1 的表格里逐条写明。

B7 商品退货、B3 商品报损各有独立入口；预订到期由系统处理，见 R-11。

## 3 业务规定（R-1 ~ R-26）

业务规定来自场景需求、经营者的政策选择、角色职责和各动作必须保持的数据关系。先明确“谁在什么条件下做什么、结果如何、失败或撤销时怎么办”，再落实为表与约束；不能仅凭已有表结构反推经营政策。

本项目的需求来源是课程材料与组员确认的模拟书店场景，并非真实门店访谈。三天预订期、会员年限、卡费、折扣和积分比例属于本组设定；库存、积分与流水相等属于一致性要求。课程要求与项目自行选择应分别说明，AI 建议经组员确认后才成为正式规定。

| # | 规定 | 挂在哪条业务 |
|---|---|---|
| R-1 | **「能不能卖」= 两个量**：**上架**（布尔，**只由店长决定，完全不做自动化**）+ **可售量**（数量，由业务派生）。能不能卖 = 上架 **且** 可售量 > 0。<br>**不设商品状态机**：「待定价 / 下架 / 停售」全部塌缩为"未上架"；**「缺货」也不用任何标记或状态** —— 它就是 `可售量 = 0` 这个**条件**，现算即可。因此**卖光不改上架标记**，补货一到**自动恢复可卖**，不必再走一遍店长 | B1 |
| R-2 | **展示口径**：内部（库管 / 店长 / 收银员）可查看 **可售量、已订量、在架总量、上架与否**；顾客只看到**已上架**商品。已上架但 `可售量 = 0` 时显示「暂时无货」，不能购买或预订。可售量由 `在架总量 − 已订量` 现算，不落字段 | B11、B4、B5 |
| R-3 | 报损**必须填文字原因** | B3 |
| R-4 | **「订走未取」三禁**：不能卖 / 不能再订 / 不能报损 | B4、B5、B3 |
| R-5 | 采购状态为草稿 → 已提交 → 已审批 → 已收货。库管或店长可取消草稿、已提交申请；店长不批准时直接取消，不增加驳回状态。审批后不可取消，按 R-26 付款、取货入库；已取消单据保留且不能恢复，需要时另开申请。 | B2 |
| R-6 | **一张采购单只对应一个供应商**（报价可以多家） | B2 |
| R-7 | 先打折、后扣积分：原价小计 `S = Σ(单价 × 数量)`；折后金额 `B = ROUND(S × 折扣率, 2)`。可用积分上限 `Pmax = min(max(当前积分余额, 0), floor(B × 20% × 100))`。实际使用积分 `P` 必须为整数且 `0 ≤ P ≤ Pmax`，超限拒绝并提示重新选择，不自动调低；抵扣金额 `D = P / 100`，实付 `B − D`，获得积分 `floor(B − D)`。抵扣上限向下取整到分；负余额不能抵扣，但有效会员新消费仍可获得积分以抵消负余额。非会员或会员已过期时折扣率为 1，不获得或抵扣积分。 | B4 门店销售、B6 到店取货 |
| R-8 | **成交快照**：**销售单**的**行**存**成交价**（与数量）；**单头**存**会员卡档位**、**折扣率**、**原始总额**、**积分抵扣金额**与**成交金额** —— 事后再调价、改规则都改不动它 | B4、B6 |
| R-9 | 退货按原销售明细受理，支持部分退货，不设退货时间期限，不另设质量审核流程。凭销售单号核对原行与剩余可退数量，同次退货明细必须属于同一原销售单，各行累计退货数量不得超过原销售数量。回收商品入库，损坏商品另走 B3 商品报损。 | B7 |
| R-10 | **销售单状态机**：已付 / 部分退款 / 已全退 | B4、B6、B7 |
| R-11 | **预订有效期 3 天** + 到期自动过期：**由系统自动触发，没有执行角色**（技术实现留到后面） | B5 线上预订与取消（产出的规则） |
| R-12 | 预订单由有效转为已取、已过期或已取消。只允许整单取货；顾客要改商品或数量时，先取消原预订并释放全部已订量，再办理门店销售。已取、已过期、已取消为终态，不能再次取货或取消；同一次请求重试按 R-22 返回原结果。 | B5、B6 |
| R-13 | 预订**不冻结**金额 / 折扣 / 积分；自提时按**当时**的售价与**卡档位**重算 | B5、B6 |
| R-14 | 过期 / 取消**不产生资金流水** | B5、B14 |
| R-15 | **盈亏拆两个指标**：<br>① **经营盈亏** = 只算各业务**自动产生**的收付（B2 采购付款、B4 / B6 销售收款、B7 退款、B8 办卡费）；<br>② **现金余额**（= 店内资金总额）= 全部收付，**含店长的注资 / 提现** | B15 |
| R-16 | 收付实现制；库存积压不进盈亏；不做会计口径毛利 | B15（另见 `docs/spec-scenario.md` §5 边界声明） |
| R-17 | **会员卡档位与权益**：目前设银卡、金卡两档。银卡初始办卡费 20 元、折扣率 0.95；金卡初始办卡费 50 元、折扣率 0.90。两档费用均大于零，金卡费用严格高于银卡，金卡折扣率不得高于银卡；不支持免费办卡或零差价升级。店长可修改两档的当前办卡费和折扣率；修改后只影响新办卡、换卡和新成交，不回改历史销售快照。会员身份在结算时生效；非会员无折扣、无积分。积分换算和抵扣上限仍按 R-7 固定 | B8 会员办理、B9 会员卡档位配置 |
| R-18 | 购买会员卡获得一年权益，有效至到期日当天结束。以门店当地日期判断，当前日期不晚于到期日即有效；首次办卡从办理日期加一年，2 月 29 日加一年若目标年无该日期则取 3 月 1 日。到期后不享折扣、不获得或抵扣积分，但正负积分余额均保留，重新买卡生效后恢复使用；到期后退原会员消费，仍回滚原单获得积分。 | B8 会员办理 |
| R-19 | **每张单据都有一个单号** —— 采购申请单、销售单、预订单和退货单均可据此指认。销售、预订与退货凭证交给顾客；预订单对外的编号就是「预定码」，不另起一个 | B2、B4、B5、B6、B7 |
| R-20 | **退货凭单号即认单** —— 不需要会员身份，也不要其它证件：**非会员凭单号同样能退**。会员也可以凭手机号找回自己的单，两者取其一即可 | B7 |
| R-21 | **所有在架数量变化都必须留下变动记录**；原因只有购入、卖出（含到店取货）、退货、损坏（报损）四类。预订、取消、过期只改变已订量；在架总量必须等于变动记录的累加，任何人不得手调。购入、卖出、退货的变动应指向对应单据或明细；报损无单据，留操作人与原因 | B2、B3、B4、B6、B7 |
| R-22 | 操作人及时间的记录范围见 `spec-roles.md` §4 第 4 条，留痕对象见下表。对同一次收货、取货、退款、取消或其他写入请求的重复提交，只处理一次并返回原结果，不重复改变库存、积分或资金；不同请求尝试操作不允许处理的终态单据应拒绝。请求识别方式由实现阶段确定，不增加新的经营业务。 | 除"只查询"类以外的**全部业务**；**留痕对象见 §4** |
| R-23 | **已订量 = 全部「有效」预订单的行数量之和**。预订增加、取消或过期释放已订量；预订阶段在架总量不变，商品侧计数须与预订明细对得上 | B5、B6、B11 |
| R-24 | 档位不随消费自动变化，不允许降档。有效银卡可按当前两档费用差价升级金卡，到期日不变；按当前全价重买同档或高档时，尚有效的从原到期日顺延一年，已过期的从本次办理日期起算一年。新到期日及闰日规则按 R-18；收费使用办理时的当前配置。 | B8 会员办理 |
| R-25 | 积分余额等于积分流水之和，不得手改；退货可能使余额为负。已用于抵扣的积分不返还，只退原单实付。设原价小计 S、原实付 A、原获得积分 E、累计退回商品原价小计 T（按原成交单价乘累计退货数量）：本次退款 = ROUND(A × T / S, 2) − 此前累计退款；本次回滚积分 = floor(E × T / S) − 此前累计回滚积分。全退时累计退款恰为 A、累计回滚恰为 E。零退款或零回滚不生成零额资金或积分流水，退货明细仍保存数量和退款额。 | B4 门店销售、B6 到店取货、B7 商品退货 |
| R-26 | 本项目假定供应商每次按采购申请正常足量交货，不考虑缺货、超量、供货失败或其他差异。审批后店长按申请数量乘批次进价的合计一次付清，库管一次取货入库并结束采购单；不支持分批收货、分期付款。入库数量必须与采购明细数量一致，异常数量不属于本项目支持流程。 | B2 商品采购 |

## 4 留痕对象清单（R-22 附表）

| 留痕对象 | 为什么值得记 |
|---|---|
| 采购申请的**审批人** | 花钱的决策要有人负责；采购付款发生在审批后、入库前，由资金流水另记店长与付款时刻 |
| 销售的**收银员** | 收错钱能追 |
| 退货的**受理人 + 退款** | 钱往外走，最需要追 |
| 预订的**取货核销人** | 取货码被冒领 / 重复核销能追 |
| 报损的**登记人** | 货没了总得有人说明 |
| 资金的**登记人** | 注资 / 提现 |
| **定价人**、**会员卡参数设定人**、**账号维护人** | 改价格、改卡档位参数、发账号都要有出处 |

采购收货人和收货时刻记在库存变动中，采购单头不重复保存。

## 5 完整性

- **15 条业务**：每条都有明确的执行角色（见 §1 各表的「谁做什么」）。
- **角色职能**：逐条都能落到某条业务上，职能清单以 `docs/spec-roles.md` §2 为准。历史周计划中的旧编号不用于当前对齐。
- 两边**没有悬空项** —— 既没有"没人做"的业务，也没有"无处安放"的职能。
